# 2026-09-13 开发日志

## 完成

### 音轨栏重做：片段（Clip）系统（第二阶段·第三批）

按用户要求把音轨栏做成 Cubase 风格的排列区，并给编辑栏补上「以片段为窗口」的语义。

**Core 数据模型**（`Core/Types.h`，新建片段默认长度常量 `kDefaultClipTicks` = 4 小节）

- `Clip { id, name, startTick, lengthTicks, loopLengthTicks, looped, notes[] }`。
  `lengthTicks` 是片段在时间轴上的**窗口长度**，`loopLengthTicks` 是**一节的长度**（循环周期），二者分开。
- `Note.startTick` 语义改为**相对片段内容原点**：移动片段天然带动音符，循环时内容按 `loopLengthTicks` 平铺。
- **音符不限于窗口内**：落在 `[0, lengthTicks)` 内的才发声，之外的保留但静音。
  这正是「片外可写但不响」与「拉长片段露出更多内容」的同一套机制。
- `InstrumentTrack.notes` → `clips[]`；`Project` 增加 `nextClipId`。

**纯函数**（`Core/MusicMath`）：`clipRepeatCount` / `expandClip`（循环平铺 + 窗口裁剪，产出带绝对 tick 的
`ClipNotePlacement`）、`trimOverlapsInTrack`（裁剪邻居保证不重叠，且内容锚定在时间轴上——
从左边裁时要相应平移音符的相对位置）、`findFreeSlot`（贴片段时找第一个放得下的空位）。

**播放**（`SynthEngine::buildSchedule`）：逐轨逐片段展开，循环片段按周期平铺、超出 `lengthTicks` 的部分裁掉，
再把相对 tick 换算成绝对 tick；同一音符在不同重复里用不同 note id，避免互相抢占。

**序列化与迁移**（`Core/ProjectDocument`）：新增 `clips` 字段（含 `loopLengthTicks` / `looped`）与 `nextClipId`。
**旧工程迁移**：加载时若音轨没有 `clips`（或为空）却带旧版 `notes`，就把该轨全部音符包成一个片段
（起点 = 第一个音符起点，长度 = 到最后一个音符结束），旧工程照常打开、照常发声。

**音轨栏**（`UI/TrackArea` 重写）

- 顶部两条与编辑栏**共用视图**（同一套 `pixelsPerQuarter` 与 `horizontalOffsetTicks`）：时间轴标尺 + 节拍标记轨，
  行为与编辑栏里的那两条一致，滚轮 / `Shift` / `Alt` 手势也一致，两边滚动与缩放联动。
- 每条音轨一行片段：片段色（默认取音轨颜色）、名称、内部音符缩略图、循环时的平铺分隔线。
- 长按约 300 ms 后拖动创建片段（出现预览与提示，左右拖动决定起点与长度）；
  点击片段 → 选中该片段与所属音轨并在编辑栏打开它；点击空白 → 只选中音轨、清除片段选择；右键删除片段。
- 拖动片段整体移动，音符随之移动，可纵向拖到**别的音轨**（音高不变，换的只是乐器）。
- 右侧中部手柄 = 打开循环并拉长（内容按一节平铺）；右下角手柄 = 只改长度；左边缘 = 改起点（右边缘不动）。
- 片段之间不允许重叠：拖动或拉伸导致相交时自动裁剪相邻片段。

**编辑栏**（`UI/PianoGrid`）：显示的是当前打开的片段，窗口 `[startTick, startTick + lengthTicks)` 正常绘制，
窗口外变暗且音符以暗色绘制、不发声；窗口外仍可写、可框选、可拖动、可复制。
所有 tick 换算统一加减片段起点。没有打开片段时画布只显示提示，不接受写入。

**复制粘贴**（`UI/MainComponent`，音符与片段各一份独立剪贴板，均不跨应用）

- 音符：选中后 `Ctrl+C`；`Ctrl+V` 粘到**当前打开的片段**、起点对齐播放头；若超出片段末端则自动拉长片段。
- 片段：选中后 `Ctrl+C`；`Ctrl+V` 粘到**当前选中的音轨**、起点对齐播放头；与现有片段重叠时顺延到第一个空位。
- 音符只能粘在编辑栏、片段只能粘在音轨栏；上下文不对时静默忽略。

**选项栏**新增「片段」一节：名称（可改）、长度与循环状态读数、**循环开关**。

### 片段重复 N 次（同日续做）

给片段补上 Cubase 的「重复」：选中片段后 `Ctrl+D` 复制一份，或点选项栏「重复 N 次…」按钮输入份数。

- **纯函数** `MusicMath::repeatClip (track, clipId, count, nextClipId)`：副本保留源片段的内容、长度与循环设置，
  音符仍是片段相对坐标，所以复制完各自独立。每份落在**第一个空位**上，`nextClipId` 每份前进一次，
  返回新片段 id 列表。
- 命令入口是 `MainComponent::repeatSelectedClip (count)`（`Ctrl+D` 走 1，按钮走对话框输入的份数），
  一次命令只压一条快照，所以「重复 3 次」撤销一次就全退回。
- 对话框在 `showDialogs == false`（离屏自检）时自动退化为复制一份，不会挂住无人值守的运行。

**这里改了两次语义**，值得记下来：

1. 最初把副本按 `源起点 + (i+1) × 长度` **紧挨着放在源之后**，再 `trimOverlapsInTrack` 裁掉挡路的片段。
   结果**连按两次 `Ctrl+D` 不增长**——第二次的副本正好压在第一次的副本上，把上一次的成果裁没了。
   自检立刻抓到：`got 3`（源 + 两份，但其中一份是覆盖出来的）。
2. 改成**依次找第一个空位**（`findFreeSlot` 从源末端起，每放一份把游标推到该副本末尾）。
   于是连按 `Ctrl+D` 是不断把阵列加长，且**永远不会删掉已有片段**；代价是繁忙音轨上副本会顺延，
   不会再「覆盖式重复」。这条已写进需求 D44。

## 修复（同日，实现过程中自查）

长按创建片段一开始完全不工作，查出两个都是真 bug：

1. `TrackArea::mouseDown` **没有重置拖动状态**：进入时 `dragStarted` 还是上一次的残留值，
   于是长按被立刻判成「已在拖动」而取消，创建流程根本走不到。
2. `TrackArea::timerCallback` 是个**空壳**（早先简化重写时遗漏）：长按状态机没有推进，
   永远停在「待创建」。修法：定时器负责推进状态与视觉提示，
   同时用 `longPressStartMs` 时间戳判定是否满足 300 ms，使**不服务定时器的消息循环**（离屏自检）也能创建片段。

另有一处是**测试自身写错**：粘贴后片段长度应算到音符时值（2640）而非节拍整数（2400），改的是断言不是实现。

#### 用户反馈：算法图库看不到缩略图（本轮交付后）

用户报「我看不到缩略图」——打开音色窗口的算法图库只看到 32 个空方块。

**原因**：`AlgorithmDiagram::layoutBoxes()` 只在 `setAlgorithm()` / `setThumbnail()` 里被调用，
而算法图库的 32 张缩略图是在 `SynthEditor` 构造函数里、组件尺寸还是 **0×0** 的时候建好的
（`setThumbnail(true)` + `setAlgorithm(i + 1)`）；之后父组件给它们真实尺寸时
`AlgorithmDiagram` 没有覆写 `resized()`，算出来的方块矩形就**永远停在空值**，
每张图只剩一块背景板和外框，方块、调制线、输出条全都不见了。
（大图谱当场没露馅，是因为它在 `refresh()` 里调 `setAlgorithm()`，那时组件已经有尺寸；
但只要缩放窗口，它同样会按旧尺寸画——同一个根因。）

**修法**：`AlgorithmDiagram` 覆写 `resized()` 调 `layoutBoxes()`，几何永远跟着实际尺寸走。
顺手把缩略图底色改成与大图谱一致的 `gridBackground`（方块是 `panelRaised`，对比才够），
并把方块最小高度从 12 px 降到 7 px、字号随方块高度自动收，让六层深的堆叠在 92 px 高的格子里也摆得下。

**为什么自检没抓到**：原来的断言只验了「32 个格子有真实尺寸」（那是 `SynthEditor` 设的），
没有验「格子**内部**画出了东西」。现在补两条：每张缩略图内部的运算器方块矩形都非空、
快照里方块描边像素数 ≥ 3000（修前几乎为 0，修后约 49415）。

### 参考线比率箭头（同日续做，第三阶段·第六批）

用户要求：鼠标停在第二类的**目标频率族**实线上时，画一条竖直箭头，箭头端在所指的那条线上，
尾端在「所指频率 ÷ 比率」或「× 比率」得到的那条线上，旁边标 `正/负 + 频率比`。

做法：`ReferenceLine` 增加两个**纯显示**字段 `ratio` 与 `targetSide`（`+1` = `f0×r` 族、
`-1` = `f0÷r` 族），由 `buildReferenceLinesForEntries` 在 `noteRatio` 分支打上——画布于是能
自己说明一条线的来历，不必反过来去查状态栏；派生数据不进工程文件。判定逻辑抽成 Core 的纯函数
`describeRatioArrow` / `ratioArrowLabel`，界面只负责画。

`PianoGrid` 里新增悬停状态（只存 `hoveredLineHz` 与鼠标 x，绘制时按频率在新线表里找回那条线，
所以隐藏条目、切独显、改比率都会自动让箭头消失）、`mouseExit` 清空，以及
`paintRatioArrow`（插在拖动预览与播放头之间，画在音符之上）。

用户确认的三个默认值：箭头**跟随鼠标**（画在指针右侧 16 px，避免被指针挡住）；
尾端在屏幕外时**照画并裁到边缘**（1:9 的跨度超过 3 个八度，这正好表达「来源在更远处」）；
鼠标停在**虚线**（基准音自己的八度族）上**不给**提示。另外 `正/负` 跟随**箭头方向**，
不跟随乘法/除法——比率小于 1 时两者相反，以方向为准。

顺带修掉同一处的一个真缺陷：`PianoGrid::findReferenceLineAt` 原来把指针指向局部 `std::vector`
的元素后返回（悬垂指针），调用点紧接着 `line->hz` 读的是已释放内存。现在返回
`std::optional<ReferenceLine>` 的副本，写音符与悬停共用它；另加 `music::findLineNear` 提供同样的
「按频率取副本」。

**踩坑记录（重要）**：改完 `MusicMath.h`（给 `ReferenceLine` 加字段）之后，我先用
`cmake --build app-build5` 做了**增量**构建，结果跑自检时进程在参考组线段那一步崩了
（`0xC0000005`，按 map 还原地址正好落在 `juce::emptyString` 这个数据符号上），并且线段尺寸报 0×0。
原因就是 `docs/05-build-env.md` 里记过的那条：本机 Ninja 不跟踪头文件依赖，增量构建留下的目标文件
还按**旧的 `ReferenceLine` 大小**（少了两个字段）访问 `std::vector<ReferenceLine>`，内存被踩坏。
改用 `build_app.bat`（每次从空目录重建）后一切正常。**结论：动了头文件就必须整目录重建。**

#### 用户反馈：箭头要在鼠标尖上、文字要在箭头端（同日续做）

用户看了实际效果后提了两点：箭杆**略往左移、放到鼠标尖的位置**（原来画在指针右侧 16 px），
以及说明文字**改到箭头端**（原来在箭杆中点），并且**不能与鼠标重合**。

改法：`shaftX` 直接取鼠标所在列（保留离边缘 10 px 的夹取，免得画到画布外）；`plateY` 改为以
`headY` 为中心、仍受编辑区边界夹取。第二条要求有个前提——鼠标就在箭杆上，而标准箭头光标的图形
是从热点**向右下**延伸约 11 × 19 px，所以文字板只有放**左侧**才不会被指针压住：默认放左侧
（右边缘距箭杆 6 px），左侧放不下时才翻到右侧并把间距放宽到 `kRatioArrowLabelGapRight = 16`。

诊断接口顺势分细：`getRatioArrowBoundsForTest()` 只返回**箭杆 + 箭头端**（这样「上边 = 一条线的 y、
下边 = 另一条线的 y」的既有断言继续成立，并新增「水平中心 = 鼠标 x」），文字板另给
`getRatioArrowLabelBoundsForTest()`，用来断言它居中于箭头端并且**不包含鼠标点**。

悬停点也从 `tick = 0` 改到 `tick = 1920`：贴着画布最左边缘时箭杆会被 10 px 边界保护夹住，
就测不出「箭杆跟着鼠标尖」这条；另外补了一条边缘用例，确认左侧放不下时文字确实翻到右边。

### 「指示线」开关 + 拖动后箭头消失的修复（同日续做，第三阶段·第七批）

用户反馈：**写完一个音符（写完会自动选中它）之后再选频率比，把鼠标指到目标频率线上没有箭头**。

查出来是 `PianoGrid` 的拖动状态没收尾：`dragActive` 在 `mouseDrag` 里置真，却**只在 `mouseDown` 里
被清掉**，`mouseUp` 从头到尾没碰过它。而画箭头的条件里有一条「正在拖动就不画」，于是**任何一次拖动
（写音符、移动、拉长度、框选）之后，箭头都会消失到下一次按下鼠标为止**。写音符恰好就是一次拖动，
所以复现得最稳定。修法：`mouseUp` 一进来就把 `dragActive` 存成 `wasDragging` 并立刻清掉，
分支里改用 `wasDragging` 判断（框选那段要用旧值决定是否补最后一次选择）。

自检里原本没抓到，是因为那条用例是**直接 `mouseMove`** 悬停的，而它前面最近的一次操作恰好是
`mouseDown`（顺手把标志清了）。现在补了一条真正复刻用户流程的回归用例：在 660 Hz 线上合成
`mouseDown` / `mouseDrag` / `mouseUp` 写下一个音符 → 按 `2` 切 1:3 → 悬停 220 Hz 目标线 →
断言箭头出现且标签是 `负 1:3`。

同时按用户要求加了**「指示线」开关**：参考线控制栏底部（状态列表与操作提示之间）一行 26 px，
左边标签「指示线」、右边按钮，文字与状态列表同规矩——可见时写「隐藏」、隐藏时写「显示」。
开关存在工程里（`view.ratioArrowVisible`，旧工程缺字段按可见读），切换走 `applyEdit`（一次撤销记录）。

随后用户又要求**把这一行做成参考线状态行的样子**（见下一节），于是它从 26 px 的「标签 + 按钮」
变成 54 px 的三行行样式。

实现上让「隐藏」只影响**绘制**而不影响**悬停跟踪**：`updateRatioHover` 照常记录鼠标在哪条线上，
只是不重绘；`currentRatioArrow()` 在开关关闭时返回不可见。这样关掉后鼠标划过目标线不再有任何重绘开销，
而重新打开时（面板的变更广播会触发 `PianoGrid::refresh`）箭头**立刻**回到鼠标所在的那条线上，
不需要再动一下鼠标。

#### 「指示线」做成参考线状态行的样子（同日续做）

用户觉得原来那行「小标签 + 右侧按钮」和上面一列状态行不在一个调上，要求改成同样的样子。

做法是**把状态行的三带几何抽成共享常量**（`kRowInsetX / kRowTypeTop / kRowTypeHeight /
kRowNameTop / kRowNameHeight / kRowButtonTop / kRowButtonHeight`），`EntryRow` 与新的
`paintIndicatorRow` 都从这一份常量算位置——这样「长得一样」不是靠复制数值维持的，
以后改行高也不会只改一半。行的构成：高 54 px、底色用状态行未选中时的
`panelRaised.withAlpha (0.45f)`、左侧 4 px 色条用 `theme::accent`（箭头本身的颜色）、
第一行 10 pt 灰字「指示线」、第二行 11.5 pt 的 `已显示` / `已隐藏`（隐藏时改用 `dimText` 变暗，
和状态行「条目隐藏时名称变暗」一致）、第三行一个按钮，槽宽沿用状态行的
`jmax (30, (条宽 − 8) / 5)` 并放在第一格，因此与上面每行的第一个按钮左边缘对齐。

两行文字改由 `OptionsPanel::paint` 直接绘制（像 `EntryRow` 那样），原来的 `indicatorLabel`
子组件删掉了；行的上下各留 4 px，上方那段空隙里画一条 1 px 细线把它和列表分开。

**踩到的坑**：`OptionsPanel::paint` 原来在「状态列表为空」时提前 `return`（画完
「还没有参考线状态」就返回），如果按直觉把新行的绘制加在函数末尾，列表空的时候这一行就会消失。
现在把它放在那个分支**之前**。

自检相应收紧：行尺寸断言从「248 × 26」改成**高必须等于 `indicatorRowHeight`**、
在行矩形内数强调色像素 ≥ 150（4 × 54 的色条恰好 216 px）、第二行文字在
`已显示` / `已隐藏` 之间往返，并新增快照 `22-indicator-row.png`（只截控制栏本身）。

### DX7 式 FM 合成器（同日续做，第三阶段·第二批）

用户要「类似雅马哈 DX7 的 FM 合成器」并允许联网查资料。**联网申请到了权限但沙箱把出口封掉了**
（`github.com` 在 DNS 上被指到 127.0.0.1，curl 直接 http=000），所以按既有知识实现：
架构照 DX7 的惯例（六运算器、32 算法、RATE/LEVEL 包络、反馈、LFO），**算法路由表与预设都是本项目自己写的**，
没有抄任何厂商 ROM 数据。

- **模型**（`Core/Types.h`）：`FmOperator`（ratio / detune / outputLevel / velSens / rateScale /
  rate[4] / level[4]）、`FmPatch`（六个运算器 + algorithm / feedback / LFO / transpose）、
  `SynthParams` 变成「FmPatch + gain + 低通」。删掉原来的 `Waveform` 与波形渲染。
- **引擎**：每声部六个运算器，固定从运算器 6 迭代到 1（约束是「调制器编号一定大于被调制的目标」，
  于是不需要按算法排序）。相位调制幅度 = 调制器电平 × 2 个周期；包络 R1→L1→R2→L2→R3→L3 保持→
  音符结束走 R4→L4；速率曲线 `0.0015 × 5000^(1−r)` 秒，映射函数放 `Core/FmMath.h` 供工程迁移共用。
  力度既乘整体输出、又按 `velSens` 压低各运算器电平（需求要求「力度一定听得出来」）。
  运算器 6 自反馈上限 0.35 周期；LFO 五种波形、可延迟淡入。
- **32 个算法**写成表（`modulators[6]` + `carriers` + 一行连线示意），编辑器里直接显示示意文字。
- **预设**：`Core/FmPresets.h` 十五个原创音色（电钢琴 / FM 钢琴 / 钟琴 / 管钟 / 铜管 / 弦乐 / 贝斯 /
  马林巴 / 风琴 / 击弦古钢琴 / 长笛 / 铺底 / 拨弦 / 打击乐 / 口琴）。新建合成器轨自动套用电钢琴。
- **编辑器**重写成四页（算法 / 运算器 / LFO / 输出）+ 预设下拉 + `<` `>` + 底部试听键盘，窗口放大到 780×560。
- **迁移**：旧工程的 `waveform + ADSR + fmRatio/fmDepth` 折成算法 1 的两运算器音色
  （ADSR 秒数 → RATE，fmDepth 周期数 → 调制器电平）。

踩到的两个真问题：

1. **栈溢出**（`0xC00000FD`）：六运算器让 `TrackSynth` 变大，64 轨 × 16 声部放在 `PlaybackEngine` 里
   直接把栈顶穿（自检里 `MainComponent` 本身就在栈上）。改成 `std::vector<TrackSynth>`，`prepare()` 时 resize。
2. **又一次「改头文件不重编」**：改完 `AudioEngine.h` 只做了增量构建，链接出来的程序仍按旧结构体布局，

### 用户反馈：横向滚动时片段盖住了音轨头

用户报「左右滚动音轨时，片段覆盖在了乐器上方」。这是真 bug：

`TrackArea::clipBounds` 的左边界是 `headerWidth + xForTick (startTick)`，而
`xForTick` 返回的是 `(tick - horizontalOffsetTicks) × 缩放`。横向滚动之后
`horizontalOffsetTicks > startTick`，偏移变成负数，片段矩形就从音轨头**里面**开始画了——
圆角填充、边框和片段名一起盖到左侧的乐器名上。命中测试早就有 `point.x < headerWidth` 的保护，
所以只有绘制漏了。

修法：把片段绘制（以及长按创建时的预览矩形）放进一个
`ScopedSaveState` + `reduceClipRegion (headerWidth, laneY, width - headerWidth, laneHeight)` 里，
只允许画在音轨的「内容区」内。**不能用 `clipRect.getIntersection(...)` 截断矩形**，
因为片段内的音符缩略图是按 `clipRect` 的宽度和左边界做时间映射的，截断矩形会把缩略图算歪；
裁切绘制区域则不影响几何。

回归测试用**两张快照逐像素比对**：`horizontalOffsetTicks = 0` 与 `= 960` 各截一张音轨栏快照，
断言音轨头矩形内逐像素完全相同。去掉裁切后这条立刻报出 10706 个差异像素，确认测试有效。

**⑤ 拖动到边缘自动横向滚动**——`PianoGrid` 新增 30 Hz 定时器，`TrackArea` 复用它已有的那个。
拖动（音符的写 / 移 / 改长度 / 框选，片段的创建 / 移动 / 拉伸）期间，若鼠标最后一次位置落在
画布左 / 右边缘 24 px 内，就按 12 px / 次滚动视图，再把「钉在边缘的鼠标位置」重放给拖动逻辑——

顺手把 `PianoGrid::mouseDrag` 里「按位置重算预览」的那段抽成 `replayDragAt`，定时器与鼠标事件共用。

### 旁视（其他轨道的音符）+ 静音改空心（同日续做，第三阶段·第九批）

用户要求：编辑栏加一个「旁视」按钮，勾选后把**其他轨道**的音符淡淡地显示出来；
这些旁视音符只能看，不能移动 / 删除，但可以被用来「显示参考线（可以选择比率）」和「构建参考（线）组」；
同时把「被静音」改成空心，避免和旁视撞色。

**做法**：

- `AppState` 新增本次会话的 `ghostTrackIds`（勾选的轨道）与 `GhostSource`（被点中的旁视音符），
  以及 `toggleGhostTrack / clearGhostTracks / setGhostSource / clearGhostSource`。
  **旁视源与当前轨单选互斥**：点旁视音符清空当前轨选中，选当前轨音符清空旁视源——第二类参考线
  因此永远只有一个来源。
- `PianoGrid::paintGhostNotes` 画在参考线之上、当前轨音符之下：勾选轨道的每个片段用
  `music::expandClip` 展开成绝对位置，以轨道色 **alpha 0.30 实心 + 0.45 细边**绘制，不画备注与选中框。
- **旁视音符天然不可编辑**：`hitTestNote` / `findNoteAt` 只看当前片段，旁视音符根本不在里面，
  所以选不中、拖不动、框选不到、右键删不掉——这一条不需要任何拦截代码。
  新增的 `findGhostNoteAt` 只服务「点它当参考源」这一件事，并顺带返回它属于哪条轨道 / 哪个片段。
- `handleReferencePick` 的入参从 `const Note&` 改成**频率**（`double hz`），于是「选择基准音」与
  「应用」三个调用点里，当前轨音符与旁视音符走的是同一条路。
- 音符编辑窗口新增**旁视模式**：标题写「旁视音符」、频率框切只读并显示它的频率、隐藏力度 / 备注 /
  静音这些编辑控件，只留六个比率按键与目标频率读数；`applyRatio` 的「恰好一个来源」条件
  扩展为「恰好一个当前轨音符**或**存在旁视源」，快捷键 1–6 因此照样可用。
- 参考线控制栏：`ReferenceLineEntry` 加一个只用于显示的 `fromGhost`，第二类的类型文字于是显示
  `旁视音符频率-选中比率`；锁定 / 显示 / 独显 / 颜色 / 删除与「与第四类互斥」全部沿用。
- **静音改「有颜色的空心」**（用户中途补充）：只画 1 px **轨道色**描边、不填充。
  三种状态一眼可分：**实心 = 正常、空心 = 静音、淡色实心 = 其他轨道**。`theme::mutedNote` 随之删除。

**测试上踩的坑**：这个自检块会重建整个工程（三条轨道），于是把它后面的「备注画在音符上方」用例
依赖的音符一起清掉了。修法是在块首把 `tracks` 与 `referenceLines` 存一份，块尾用
`applyDerivedEdit`（不留撤销记录，它是测试脚手架）原样放回去。

## 决策与发现

- **「关闭运算器」= 输出置零，而不是把它从算法里摘掉**：参数与连线都留着，随时可以打开；
  并且它仍推进包络，所以按住音符时关掉再打开听起来是连续的，不会有音头或残留。
- **包络曲线本轮只读**：先把「看得见」做出来；拖动控制点要另做一套命中测试与坐标反解，留到后续批次。
- **预设存整份音色**：FM 存 patch + 增益 + 低通，采样器存含文件路径的全部参数；
  只存 patch 会让用户保存下来的「音色」与当时听到的不一致。
- **音色 JSON 只有一份实现**：项目与预设共用 `PresetStore` 里的读写函数，字段布局保持原样，
  这样旧工程依旧按「有 `operators` 就是 FM patch」判断，不会掉进旧的波形 / ADSR 迁移分支。
- **保存即改名**：保存预设会把当前音色名一起改成预设名，否则列表高亮永远停在「内置」那一条；
  重命名时如果当前音色正用着旧名字，也跟着改，高亮才不会跳走。
- **图谱不写文档**：点图谱选算法、点方块进详情、点小开关切开关才各算一次编辑，切层本身不进撤销栈。

- **切割吸附到当前网格**：切点来自鼠标却先吸附，和写音符同一套手感；跨切点的音符一分为二
  （左半保留原 id，右半新 id），这样两半都能独立选中与编辑，听感上也完全接得上。
- **粘合条件收紧**：只并「紧邻 + 未循环 + 都是音符片段」。带循环的内容是一段被平铺的窗口，
  合并它没有单一时间线可对齐；音频片段一个 clip 只能指一个文件，拼不起来。
- **导出格式按 JUCE 的实际能力给**：不是「想要什么就列什么」——MP3 写不了、AIFF 没有 32 位，
  菜单里就不该出现，否则用户点了才报错。
- **（测试）自动滚动的基线必须在 `pump()` 之前取**：定时器在拖动一开始就跑，`pump()` 会让它
  真的滚几步，「滚动前」的值要是 pump 之后取的，测出来就是「滚动后 vs 滚动后」。
  同理断言要留出吸附网格的余量（一步约 82 tick，吸附单位 960 tick，所以跑满 24 步）。

- **旁视源与当前轨选中互斥**：第二类参考线只能有一个「它跟着谁」的答案，所以点旁视音符清空当前轨
  选中、选当前轨音符清空旁视源；两者共用同一个 `currentRatio` 镜头，行为完全一致。
- **旁视音符不进命中测试**：它压根不在 `hitTestNote` / `findNoteAt` 里（那两个只看当前片段），
  所以「不能被移动、删除」这条不需要任何拦截代码，天然成立；只用一个新的
  `findGhostNoteAt` 服务「点它当参考源」这一件事。
- **静音改「有颜色的空心」**：用户中途补充要求——描边用**轨道色**而不是灰色。于是三种状态一眼可分：
  实心 = 正常、空心 = 静音、淡色实心 = 其他轨道。`theme::mutedNote` 因此删掉了。

- **「未锁定条目被下一条清掉」只对用户主动建立的参考线生效**：`＋` 新增赫兹、应用 / 启用
  参考线组时调 `clearUnlockedEntries`；而二、四类是**自动派生**的，`syncReferenceEntries`
  只替换彼此，不会顺手抹掉用户刚加的第一、三类。按字面规则「选中一个音符」也会清掉未锁定的赫兹线，
  那样第一类几乎只能靠锁定才能用；这里按「主动建立」来理解，如果这不是你要的语义，改一行即可。
- **频率比按「视图状态」理解**：用户说「改了比率、点别的音符再点回来仍然是 1:2」，
  所以比率不再存进音符，而是 `AppState` 里的一个镜头，选择一变就回 1:2。
  代价是旧的 `.nprj` 里每音符的比率被忽略，打开后一律从 1:2 开始。
- **静音不进 `projectEndTick`**：静音音符仍然占时间轴位置（滚动范围与编辑视图不跳），
  只是不产生合成器事件；因此导出长度由「最后一个可听音符」决定，而不是工程最后的位置。
- **音符 tick 相对片段**：绝对 / 相对换算只在编辑栏读写时加减片段起点，单一换算点，避免全局散布。
- **窗口外音符保留但静音**：一个机制同时满足「片外可写不响」与「拉长片段露出更多内容」，不必做两套。
- **片段不重叠 + 内容锚定时间轴**：裁剪邻居时从左边裁要平移音符相对位置，否则内容会跟着窗口一起挪，听感会变。
- **两份独立剪贴板**：复制音符不会影响片段粘贴，粘贴目标（编辑栏 / 音轨栏）不混淆。
- 参考组（参考线 / 参考线组）机制不受本次改动影响，仍按绝对频率工作。

### 第三阶段·第十一批：多选音符「应用为参考线组」+「不吸附」（同日续做）

用户要的两件事。第一件一开始被我理解错了：我以为是要把选中音符当**参考组**（左侧那条只存比率的
率制线段）用，用户回了一句「参考线组不是参考组」——参考组只存比率与圆点，**参考线组**才是

实现时发现一个数据模型上的坑：`buildReferenceLinesForEntries` 对一个 group 条目只展开它
**存着**的圆点，而位置 0/1 的框圆点按约定不入存储（那是参考组建段时的约定）。所以如果只把

一个位置 0 的圆点。第一版就是因为最后 `group.dots = scratch.dots` 把这颗圆点覆盖掉，

第二件是「不吸附」。它比看上去多一层：同一个 `snapDivisor` 既当吸附步长，又当**默认 / 最短长度**
（`commitNoteCreation` 里 `end = start + gridTicks`）。如果关吸附时把它也放开，点一下就会写出
1 tick 的音符。按用户的选择，做成「只关量化、细分仍决定默认与最短长度」，于是 `snappedTick`
在关闭时直接返回指针所在的 tick，而 `snapGridTicksAt` / `snapTicksNow` 保持原样。另外还发现
`commitNoteCreation` 与 `updateResizePreview` 里各有一处直接调 `snapToGrid` 的**二次量化**，

### 第三阶段·第十二批：节拍器与循环（同日续做）

两件事一起接在走带上。做法上有三处是刻意的：

1. **循环按 tick 存在工程里**（`loop { startTick, endTick, enabled }`），不是按秒——改速度时
   循环点要跟着走。区间用 `Shift`+拖动在**任意一条标尺**上划（音轨栏与编辑栏各有一条标尺，
   都在同一个 `TimelineRuler` 里，所以只写了一份）；`Shift`+点击清除。拖动期间只画预览、
   松手才 `applyEdit`，因此一次划区间就是一条撤销记录。
2. **回卷在引擎里做**：`PlaybackEngine` 在渲染块内把块长裁到「下一个音符事件 / 下一声节拍 /
   循环终点」三者最近的那个，走到终点就把所有声部释放、把每条轨道的事件游标用 `lower_bound`
   倒回起点。这样循环和音符调度共用同一套游标，不需要把时间轴提前展开成 N 份。
3. **节拍器不写进导出**：它只在实时监听里合成，导出用的是另一个全新构造的 `PlaybackEngine`
   （循环与节拍器默认都是关的），所以离线渲染既不会被截短、也不会有咔嚓声。这条专门加了
   单元测试守着。

节拍器的「下一拍」是纯函数（`firstClickAtOrAfter` / `nextClickAfter`），重音判定走现成的
`tickToBarBeat`（第 1 拍 + 拍内 0 tick），所以 4:4 与 3:4 的重音位置是单元测试直接验的，
不靠听。踩到的一个小坑：`TempoMap::nextBeatTick` 是**严格大于**的，所以「从整拍开始播放」
必须先用「落在拍上就取本拍」的分支，否则第一声会晚一拍。

### 第三阶段·第十五批：波表合成器（同日续做）

第五种轨道。波表不做「导入 WAV」那套（路径、周期对齐、丢文件），而是**程序生成 16 张**，
每张 8 帧、帧长 2048：

1. **帧先写成相位形状，再 FFT 转频谱**（`正弦→锯齿`、`锯齿→方波`、`奇次谐波`、`共振峰`、
   `铃声`、`脉冲宽度`、`三角→锯齿`、`谐波堆叠`、`五度堆叠`、`相位失真`、`玻璃`、`人声`、
   `锯齿堆叠`、`方波→正弦`、`谐波噪声`、`管风琴`）。形状可以随便写——方波、脉冲这种理想上
   带宽无限的形状，也正是靠后面这一步才变得干净。
2. **每个八度一张 mipmap**：从同一份频谱出发，逐级把高于 `1024 >> k` 的谐波（连同它的镜像
   频点）清零再逆变换，得到 11 级波形。播放时按 `采样率/2/频率` 选级，高音区因此不会混叠——
   这是本项目一贯的底线，而波表不做这一步会明显发毛。增益取全表最响的那一帧，所以窄脉冲这种
   带限后峰值本来就低的帧会保持它原本的音量，而不是被重新拉满。
3. **波表库是只读的**，工程里只存 `tableIndex`；库在消息线程首次构建（`buildSchedule` 与
   编辑器构造各调一次），音频线程只读。

之间插值**再在帧内插值取样本；位置 = 静态位置 + 位置包络 + LFO→位置，**夹在 0..1**（不环绕）。
编辑器是单页：左半画当前正在播放的波（与引擎共用同一份数据和插值），右半是 8 帧缩略图、当前帧
高亮；四列控件；预设行与 FM / 减法完全同一套（12 个内置 + 「我的」）。

### 第三阶段·第十七批：鼓机（同日续做）

第六种轨道 `TrackKind::drums`（序列化值 5）。用户要「一套鼓乐器」，做法上与采样器相反：
**12 个鼓全部程序合成**，工程里只存参数，不引入任何采样文件，因此也没有丢文件的问题。

**数据模型**：`Note` 增加 `pad`（-1 = 普通音符，鼓轨上频率不参与发声，只当可读占位）；
`DrumPadParams { enabled, level, pitch, decay, tone, snap }` × 12 + `DrumKitParams { name, pads[12], gain, masterPitch, masterDecay, width }`。
12 个鼓按常见排法固定：叮叮镲 / 吊镲 / 牛铃 / 高音通鼓 / 中音通鼓 / 低音通鼓 / 开镲 / 闭镲 / 拍手 / 边击 / 军鼓 / 底鼓
（`pad 0` 在格子最下一行）。

**引擎**（`Audio/DrumSynth`）：16 声部、与其它乐器同一套抢占策略，但 `noteOn` 收的是**鼓垫编号**；
每个鼓是**一次性发声**（`noteOff` 不影响它，衰减完自己释放声部）。合成方式走 808/909 那套电路感：
底鼓是「正弦 + 快速下滑的音高包络」，军鼓「两个音体 + 噪声」，拍手「三段错开的噪声爆发」，
闭镲 / 开镲「六个非谐金属分音 + 高通噪声」，通鼓「音高包络较小的正弦 + 少量噪声」，
牛铃「两个方波音」，吊镲 / 叮叮镲「明亮噪声 + 金属分音（叮叮镲另有一条清晰的 ping）」。
`tone` / `snap` / `decay` / `pitch` 各调一种性格。**闭镲掐开镲**：一次闭镲（或再敲一次开镲）
会把正在响的开镲按约 4 ms 的时间常数收掉——这是鼓机的标志性行为，单元测试直接验。

**编辑栏的鼓格视图**（`UI/PianoGrid`，当前轨是鼓轨时自动切换）：纵向 12 条鼓垫行（隔行底色 + 左侧鼓名），

### 第三阶段·第十七批补充：拖动按方向分流（同日续做）

鼓机上「普通拖动一律写音符、框选按 `Ctrl`」的手势与频率栏的 `Ctrl` 语义打架，用户要求改成
**含竖直方向的拖动是框选、横向拖动是写音符**，并且频率编辑栏也照同一条规则办。

做法是在 `PianoGrid` 里加一个**待定**拖动状态：在可写位置（鼓垫行、或频率栏命中参考线 ±6 px）
按下时先不决定干什么，只记住按下点、目标（`pad` / 参考线频率）与锚点 tick；指针第一次越过
**现有的 3 px** 阈值时用主轴判定 `|dy| >= |dx|` 分流——竖直为主转成框选（选框从按下点开始，
实时更新，`Ctrl` 取并集），横向为主转成写音符（锚点仍是按下时的 tick）。
判定一次后整段拖动不再改变；**不移动的单击仍然写一个默认细分长度的音符**。
顺带把鼓垫**钉在按下那一行**：横向拖动不再因为手抖换鼓（换鼓仍然通过拖动已有音符实现）。

保持不变的是：拖动**已有音符**（移动 / 左右边缘改长度 / `Alt`+上下改力度，竖直拖动仍是换鼓）、
频率栏**真正空白处**的框选（任意方向都是框选、`Ctrl` 取并集）、自动滚动与撤销粒度。

两处容易踩的坑，都在实现时处理掉了：

1. 判定的阈值必须与 `dragActive` 的阈值**完全一致**（都是欧氏距离 3 px），否则「斜着抖 3 px」
   会出现 `dragActive == true` 但还没分类的状态，`replayDragAt` 会掉进 `updateResizePreview`。
   分类之后还在尾部分支加了一道 `pendingWrite` 的护栏。
2. 自检里原来那条鼓格框选用的是「第 11 行 → 第 0 行、tick 1800 → 4900」的横向长条，
   方向判定一上来它就变成**横向为主**（会去写音符）。把鼓格自检的 `pixelsPerQuarter` 从 90 调到 40，
   让竖直跨度明显大于水平跨度，才是真正的「竖直拖动」。

- **离屏自检**：`work/app-build5` → `work/selftest-dragdir1`，**520 项全过、0 失败**，`crash.log` 为空。
