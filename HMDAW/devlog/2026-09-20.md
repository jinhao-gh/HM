# 2026-09-20

## 第三十七批：混音台窗口 + 工程级总输出推子 + 空格键全局走带（已完成）

用户要求两件事：一个「像 Cubase 一样的混音台界面」；以及「除在重命名状态外，
无论在什么界面，空格键都可以控制走带」。

### 做了什么

- **数据模型**：`Project::masterVolumeDb`（默认 0 dB，`.nprj` 里读回时夹到 -60…+6，
  缺字段 → 0 dB，所以旧工程打开时声音一个采样都不变）。
- **引擎**：
  - `RenderSchedule::masterGain`（`buildSchedule` 从 `masterVolumeDb` 换算），
    `PlaybackEngine::renderNextBlock` 在把整条混音交出去之前乘一次——**监听与导出共用这一段**，
    所以导出天然遵守总输出推子，不需要在 `Exporter` 里再写一遍。
  - **每轨电平上报**：`mixTrackIntoOutput` 量推子 + 声相之后的峰值写进
    `std::array<std::atomic<float>, kMaxTracks>`（按轨道 id 找槽位），`renderNextBlock` 结尾量总输出；
    `readTrackPeak / readTrackClip / readMasterPeak / readMasterClip` **读一次即清**。
    音频线程只写数字，衰减与峰值保持在 UI 侧（`Core/MeterMath.h`）。
  - **顺手做对的一件事**：以前「没有插入链的轨道」是直接加进总输出的，那条路上没有测量点，
    混音台对绝大多数轨道都会显示 0。现在**每条轨道（含音频轨）都先渲染进 `trackBuffer` → 过链 →
    `mixTrackIntoOutput`**，测量点只有一处。算术与顺序都没变（少了 40 行重复的混音代码）。
- **混音台**（新 `Source/UI/MixerWindow.{h,cpp}`，顶栏「混音台」+ `F3`，设计 980×560）：
  左边横向可滚动的条带区（`Viewport`，条带宽 92 px），最右**钉住**一根总输出条；
  条带自上而下是 轨道名 / 乐器入口 / 插入链（4 行 + 「＋」）/ 声相 / 竖直推子 + dB / M / S /
  峰值电平表；底部一行 `▶ 播放` `■ 停止` `|◀ 回到开头` + 小节:拍:刻度。
  条带上的动作全走 document（推子拖动 `beginEdit` / `notifyEdit`，一次拖动一条撤销；
  点条带 = 选中该轨；插入链的行右键 上移 / 下移 / 删除）。
- **空格键**：`MainComponent` 实现 `juce::KeyListener`，把同一个监听器挂到 HM 自己开的每个顶层窗口上
  （主窗口 / 音色 / 效果器 / 混音台 / 插件窗口；警报对话框不挂，它要自己按焦点按钮）。
  规则收在一个函数里（`isTransportSpaceKeyFor`）：**无修饰键的空格**且
  **焦点不在文本框里**（改名、比率、搜索…——那是打字）且
  **焦点不在插件自己的界面里**（Kontakt / Serum 用空格试听，`PluginWindow::getEditorComponent` 判定）。

### 踩到的坑

- **增量构建骗了我一次**：这台机器的 Ninja 不跟踪头文件依赖（见 `05-build-env.md`），
  我先用增量编译跑单测，`AudioTrack / Export / VstInstrument / EffectChain` 四个组直接崩在
  访问违例上——因为 `Exporter.cpp` / `PluginHost.cpp` 那些 `.obj` 还是**改头文件之前**编的，
  `PlaybackEngine` 里新加的原子数组改了结构大小，栈上的实例就对不上了。
  结论：**动了头文件就跑全量重建**，这条不是洁癖（`work\build_tests22.bat` / `build_app.bat` 每次清干净）。
- **总输出推子不是 -60 dB 就等于 0**：`Types.h` 的 `decibelsToGain` 是 `pow(10, db/20)`，
  -60 dB 是 0.001 倍（= -60 dBFS，实际上就是静音，但不是硬 0）。这与轨道音量一贯的约定一致，
  本批**没有**为总推子特判成 0——测试里按 0.001 断言，文档里写明，免得下一个人以为这是 bug。
- **离屏自检里文本框拿不到键盘焦点**：`Component::grabKeyboardFocus()` 要求组件 `isShowing()`，
  而自检的 `MainComponent` 从来没上过桌面，所以焦点根本不会移动。于是空格键规则改成
  「规则本身可以直接问」的形式（`isTransportSpaceKeyForTest (key, focused)`），
  自检用**真实的**轨道名输入框与**真实的**插件界面去问；能不能切换走带仍在窗口上用合成按键验证。
- **插件界面里的空格谁吃掉的**：调试打印走了一遍父链，发现插件编辑器的父是 JUCE 自己的
  `VST3PluginWindow`，它自己就把空格处理掉了（这才是 Kontakt 那类插件能试听的原因）。
  HM 的监听器在这条路上只会被问一句「要不要」，答「不要」。
- **`make_release.bat` 会把老快照一直带下去**：它清的是 `outputs\HM\screenshots\*.png`，
  但源目录 `work\release-selftest\` 从来不清理——里面还躺着第三十四 / 三十五批生成器的
  4 张图，于是每次发布都把 41 张新图 + 4 张老图一起拷进交付物（这次是 45 张）。
  修法：跑自检**之前**先清 `%SELFDIR%\*.png`。这次的交付物已手工清成 41 张，
  下次 `make_release.bat` 会自己清干净。
