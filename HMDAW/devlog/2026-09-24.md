## 第四十一批：MIDI 输入（① 输入与映射 ② 录制 ③ 片段重叠）（已完成）

用户要一条 **MIDI 输入**链路：顶栏加「MIDI输入」按键，点开的窗口左边是**竖着的钢琴键**、
右边是**参考线组**的竖线（点右侧标频率、颜色同该组），拖动把键与某个频率绑起来；
有**循环 / 非循环**两种模式、能把配置存成预设；弹下键盘就用**选中轨道**的乐器发声；
再加「录制」按钮（快捷键 `*`）、「在片段内 / 片段外录制」两种落点；最后**允许片段重叠**；
顺带「写入音符时发出声音」。

动手前先问清并确认了三件事：**分三步做、每步一次验收 + 发布**；**循环模式 = 一格在键盘上
上下循环平铺**（不是一个键一个键地数）；**重叠时两段一起发声**。另外两件事是我提的方案、
用户认可：**映射存频率数值**（不是「第几个圆点」），以及**钢琴窗模式下 MIDI 走十二平均律**
（那里画的本来就是半音格）。

### 第一步 · 输入与映射、发声、写音符试听

  loopKeys]`（**负数取模正确回绕**），非循环模式查 `free` 表（0–127）；`0` = 空（不出声、不录）。

  `shared_ptr<Delivery>` 送回消息线程（设备线程不能碰界面）。设备选择写

  `getMidiMaps / addMidiMap / replaceMidiMap / renameMidiMap / removeMidiMap`。
  窗口里的改动**不进撤销栈**（配置不是编辑），随 `Ctrl+S` 存盘。

## 第四十一批·用户反馈修复：连不上圆点、圆点颜色不对（已完成）

用户报了两件事：**「我无法将钢琴键连接到参考线组上，且圆点的颜色没有匹配参考线组的颜色」**。
两件都是真的，原因各一个，都不是玄学：

### 圆点的颜色

参考线组在画布上的颜色规则写在 `music::referenceLines` 里：**「状态条目自己设了颜色就用它，
否则用那个圆点自己的颜色」**（`line.colourIndex = entryColour >= 0 ? entryColour :
dots[i].colourIndex`，`PianoGrid` 再把它折成 `theme::trackColour`）。
而 MIDI 窗口里是一个 `dotColour()` 用 **`dots.front().colourIndex`** 给**所有**圆点与所有线
上同一个颜色。偏偏「应用参考组」建出来的组，第一个点一定是 **frame dot**（position 0，
颜色是 `kFrameDotColourIndex = 7`，浅灰）——所以用户看到的是**一整列灰点**，
而画布上 1:3 那些线是有颜色的。

改法：

- `MidiInputCanvas::dots()` 现在返回 `Dot{ hz, colourIndex }`（频率仍然排序去重，
  只是把「这条频率来自哪个圆点」一起带出来），`colourForDot` 按画布同一条规则解析，
  `colourForHz` 给每根电缆用它**所连那个圆点**的颜色（不再是全局一个色）。
- `MidiInputState` 新增 `groupColourIndex`（`.nprj` 的 `midiInput` 段与 `presets.json` 的
  `midiMaps` 段都写；**缺字段读成 -1**，不是 `(int)` 转换出来的 0）；选一组时把来源条目的
  `colourIndex` 一起存下来，条目还在时**跟条目实时同步**（条目删掉就退回存下来的那份）。
- 画布那根竖线改成中性的 `theme::outline`：画布上的组是「每个圆点一条横线、各有各的颜色」，
  这里只有一根竖轴，颜色交给圆点本身，比乱挑一个颜色诚实。

### 连不上圆点

绑定只在 `mouseUp` 时用 `dotAt()` 判落点，而 `dotAt()` 是**14 px 磁力**。
圆点之间隔着一个八度——在 900×560 的窗口里差不多 **90~150 px**——所以「从琴键往右平拖、
在柱子里松手」这个最自然的动作，几乎必然落在离任何圆点都超过 14 px 的地方：
**代码什么也不做，而且什么也不说**。加上「从圆点往琴键拖」这个方向当时根本没有实现
（`mouseDown` 不在琴键上就直接 `return`），用户的感觉就是「拖不动 / 连不上」。

改法（一次性把这两个方向都做对，并且让落点可见）：

- **落点放宽**：`dropDotAt()` —— 只要指针在**右侧那一栏里**（还可以再往左多给 40 px 余量），
  就按 **y 最近的圆点**接住；14 px 磁力仍在，用作「精确命中」的提示环。
- **方向反过来也行**：按在圆点上（`dragDot`）拖到琴键上松手同样绑定
  （`dropKeyAt()`：在琴键条里就按最近的**行**算）。
- **拖动时画预览线**：虚线从起点连到「松手会落在哪」，圆点上还有一圈环，
  所以「会绑到哪一个」在松手之前就是确定的，不再是猜。
- 顺带：**右键圆点**把连到它上面的琴键一次松开（和右键琴键断开对称）。
- 右侧栏在还没有圆点时写一句「上面选一组参考线组，这里的圆点就是能绑的频率」，
  有圆点但一个键都没绑时写「把琴键拖到圆点上即可绑定；拖到圆点附近就行」，
  状态行也会补一句同样的话——失败模式从「什么都不发生」变成「看得到该做什么」。

- 单元测试 **31 组 / 2259 条 → 31 组 / 2263 条**（`Serialization` 补 4 条：
  `groupColourIndex` 往返、圆点自己的颜色往返、旧文件缺字段读成 **-1**）。

  **从圆点拖到琴键**也能绑、**右键圆点**松开连到它的键。

## 第四十一批·第三次用户反馈：右列显示多个八度 + 左列钢琴键上下翻转（已完成）

用户接着要两件事：**右侧显示多个八度**、**左侧钢琴键上下翻转**。

第一件是上一轮「只画一个八度」的反向修正：`dots()` 恢复成**锚点上下各一个八度**
（共三个八度、按八度分块升序），一个 7 点的 C 大调组显示 **21 个点**——中间那 7 个就是
锚点那个八度，上下各再一套。`tile` 的语义没变（存的仍是**被拖的那个点的频率**，
所以拖中间八度的 C 存 261.63、拖下面八度的 C 存 130.81，弹的时候再按键盘的八度 ×2/÷2）。

第二件是**坐标方向**：左列原来是「低音在上、往下越来越高」，而右列的频率轴
（以及钢琴窗的键盘条）是**高音在上**——两边反向，看着别扭，横着拖过去也对不上高度。
现在左列也**低音在下、高音在上**：一格 12 个键的方块里第 0 个键（最低）画在最下面，
非循环模式也按同一条（`lastVisible - midiNote`），滚轮方向跟着反（往上滚 = 往高音走），
「跟着播放键滚动」的判定改成「矩形出界就滚到中间」（不再依赖上下方向）。

### 配套

- **「装不下」的判定改成按“一个八度里的第几个”算**（`Dot::slot`）：一个八度里第 M 个之后的
  圆点画灰、不能绑，但**每个八度的同一位置要么都能绑、要么都不能**——不然三个八度里
  只有第一个八度能绑，那就成了 bug。提示语改成「这一格只有 M 个半音，这一组的 N 个圆点
  装不下（把「循环键数」调大就能绑）」。
- 自检跟着改：21 个点的频率按八度核对（0..6 = ÷2、7..13 = 原值、14..20 = ×2）、
  7 条线拖到**中间八度**的那 7 个点、颜色按「一个八度里的第几个」核对、反拖与右键改用到
  第 9 / 第 7 个点；「装不下」那条改成 42 个点里 36 个装得下；另外补两条新断言：
  **C4 的键比 B4 的键低（上下翻转）**、**离最近圆点 20 px（超出 14 px 磁力）也接住**。

## 第四十一批·第二次用户反馈修复：整格跟着键盘升降八度（已完成）

用户把「怎么用」说得很具体：**用 C 大调的参考线组，把一个八度的白键连到一个八度的圆点，
点「应用」再点钢琴键 C 并按下 MIDI 键盘的 C，之后按白键应该出 C 大调、从左到右递增、
按黑键不发音**。按这个标准，当时的实现有四处在挡路，其中两处是模型本身错了：

1. **右列显示三个八度**（每个圆点向上/下各一个），一个 7 点的 C 大调组 = **21 个点**——
   根本没有「一个八度的圆点」这回事可选，手动拖 7 条线几乎必然落到别的八度上。
2. **跨八度是「平铺」而不是「升降八度」**：高八度弹出来是同一个频率，所以「从左到右递增」
   只在一个八度里成立，再往上就原地打转——这不是乐器该有的样子。
3. **左列只有 C 键写了音名**，其余 11 个键靠自己数，哪个是黑键、哪几个是空的都看不出来。
4. **学完锚点没有任何反馈**：状态行只写「已绑定 N 个键」，说不出「空几个、空的是什么意思」。

先问了用户四个问题，答案决定了做法：

| 问题 | 用户的选择 |
| --- | --- |
| 「一格」是多少 | **12 个半音（含黑键），黑键留空就不发声** |
| 跨八度怎么算 | **整组跟着升/降八度**（键盘往上走一格 = 整组 ×2） |
| 要不要「一键铺白键」 | **不要**，手动拖 |
| 右列显示几个八度 / 组里点数不定怎么办 | **只显示一个八度**；圆点多于格长时**装不下就绑不了** |
| 左列怎么标 | **每个键标音名 + 空步画「空」** |
| 学完给什么反馈 | **写明「已绑 N 个 · 空 M 个」** |
| 基准键能不能是空的 | **任何键都可以**（包括黑键/空步） |

### 做了什么

- **核心语义（`midimap::Map::frequencyFor`）**：循环模式下
  `频率 = tile[(note − 锚点) mod 格长] × 2^floor((note − 锚点) ÷ 格长)`。
  `tile` 里存的仍然是**锚点那个八度**的频率，跨八度的倍率取用时算出来；空格步在任何八度
  都不发声（空就是空）。用 `std::floor` 保证锚点以下的音往下折（`59 / 锚点 60 / 格长 12`
  → 第 11 步 ÷2），而不是朝零取整。非循环模式、`setFrequency / isBound / boundKeyCount /
  visibleNotes / setLoopKeys / isSame` 全部不动，所以工程与预设的文件格式没变。
- **右列只画一个八度**：去掉原来「上下各扩一个八度」的展开，直接画这一组自己的圆点
  （C 大调 = 7 个），频率、颜色、磁力、虚线预览照旧。
- **装不下就绑不了**：格长 M = `循环键数`，按频率升序第 M 个之后的圆点画成灰的、
  不参与落点判定（拖过去会落到最近的**装得下的**那个），栏里写一句
  「这一格只有 M 个半音，后面 N−M 个圆点装不下（把「循环键数」调大就能绑）」。
- **左列每个键都标音名**（C4 / C#4 / … / B4），**空步在键右侧写一个淡「空」**，
  绑上的键还是原来的色条 + 中列的频率文字。画与自检走同一个取文案的函数
  （`keyCaption`，钩子 `getKeyCaptionForTest` / `isStepEmptyForTest`）。
- **状态行**：平时写「锚点 C4（MIDI 60）　·　一格 12 个半音　·　已绑 7 个　·　空 5 个
  （空的不发声）」；学习态里如果用户**先按了 MIDI 键**（还没点左侧琴键），写
  「先点一个左侧琴键（Esc 取消）」——以前这一下什么都不发生。
- `应用` 的数学不变：`锚点 = 按下的音 − 被点琴键在格里的序号`，任何键（含空步）都能当基准。

### 踩到的坑

- 自检里有一条断言我一开始写错了：以为「把锚点对到 C5 之后，按 C5 应该出两倍的 C4」。
  实际不是——**锚点自己就是这一格的第一个音**（还是那一组自己的频率），要再往上一个八度
  才是两倍。这正是「应用 = 这一格从这个键开始」的含义，断言改成两条：
  `72 → 261.63`（这一组的 C）与 `84 → 523.25`（两倍）。
- 「装不下的圆点画成灰的」这条断言一开始也红了：`getDotColourForTest` 当时只算「圆点自己的
  颜色」，没有把「装不下 → 灰」这条**绘制**规则算进去——也就是「测的不是画的那个」。
  把规则收进同一个函数（画与钩子都问 `isDotBindable`）之后才对上。
- 单测里三条断言因为语义变了而变红（`64 → 100` 变成 `200`、`68 → 100` 变成 `200`、
  序列化里的 `61 → 110` 变成 `220`），都是**新语义该有的值**，逐条改成新值并写明理由。
