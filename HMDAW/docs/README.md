# HM 开发文档

它们既是给人看的说明，也是给 AI 协作者的工作依据——**动手前先读相关文档，改动后同步更新**。

## 文档维护约定

- **单一事实来源**：同一个决定只写在一处，别处引用。例如「吸附网格的定义」只在 `03-pitch-model.md` 里写全。
- **决策要带理由**：写「为什么这样定」，否则后人会重复讨论。被否决的选项也值得记一行。
- **数值必须精确**：颜色写 `0xff1b1b21`，尺寸写 `24 px`，不要写「偏暗的灰」「差不多二十几像素」。
- **改代码同时改文档**：如果实现与文档不一致，先确认哪个是对的，然后把另一个改过来。
- **文档不记录进度**：进度写在 `../devlog/` 里，这里只写「是什么、为什么」。
