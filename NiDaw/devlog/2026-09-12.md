# 2026-09-12 开发日志

## 完成

### 参考组界面（原「率制」，第二阶段·第二批）

按用户重新表述的需求实现，并全面改名：**率制 → 参考组**。

核心概念定稿：**相距八度的频率算同一类音高**（`{f × 2^k}`），于是线段恒为一个八度、
线段上所有位置都折叠进 `[0,1)`，`×3` 落在 0.585、`÷3` 落在 0.415，线段永远不需要延长。

**数据模型**（`Core/Types.h`，不含任何界面依赖，颜色用调色板索引）

- `ReferenceDot { position, colourIndex }`；`ReferenceGroup { name, dots[] }` 只存比率、不含绝对音高。
- `ReferenceLineGroup { name, anchorHz, anchorPosition, dots[], visible }`：应用时把参考组钉到一个具体音符上，
  频率在那一刻定格。
- `ReferenceLine` 增加 `colourIndex` 与 `isGroup`；`Project` 增加 `referenceGroup` 与 `referenceLineGroups`。

**纯函数**（`Core/MusicMath`）：`foldPosition` / `positionToRatio` / `ratioToPosition` /
`addDotAt` / `removeDotAt` / `findDotNear` / `dividePositions` / `referenceFrequencies` /
`buildGroupReferenceLines` / `buildAllReferenceLines`。

**预设库**（新模块 `Core/PresetStore`）：`%APPDATA%\NiDaw\presets.json`，存参考组预设与参考线组预设，
支持改名、删除、跨工程复用；文件缺失按空库处理，文件损坏时报错但不影响启动。

**界面**

- `OctaveLadder`：线段画布。对数刻度、多八度周期重复、滚轮滚动、`Alt`+滚轮以鼠标位置为锚点缩放；
  点圆点选中（`Ctrl` 多选）、点叉点变圆点、右键圆点删除；叉点为临时预览层。
- `ReferenceGroupPanel`：编辑栏**左侧**常亮的一栏。顶部「历史 / 预设」，中部线段，
  下方 8 色色板、六个比率按键 + 自定义、等分输入，底部「选择基准音 / 保存预设 / 应用」。
- `PresetPanel`：参考组栏旁的侧栏，历史与预设两种模式，预设面板可在参考组预设与参考线组预设间切换。
- 选项栏的「率制」占位换成**参考线组状态**列表：每组一行，含颜色标记、名称、显示/隐藏、删除。
- 编辑栏布局：参考组栏 | 侧栏 | 可拖拽分隔条 | 画布 | 选项栏。

## 修复（同日，用户试用反馈）

用户试用后报了三个问题，前两个都是确切的 bug：

1. **线段两个端点被当成同一个点，无法选中两端做整八度等分。**
   `OctaveLadder::selectDot()` 第一行就 `foldPosition(position)`，而 `fold(1.0) == 0.0`；
   于是 `Ctrl` 点第二个端点时被判定为「已选中」，反而把第一个取消，最终两边都没选中。
   核心的等分数学其实是对的（`dividePositions(0,1,n)` 能正确划分整个八度），坏的只是选中状态的表示。
   修法：选中位置改为**不折叠**存储与比较（0 与 1 各自独立），并把这段逻辑抽成
   `MusicMath::toggleSelectedPosition` / `isPositionSelected` 两个纯函数以便单元测试；
   端点旁补上 `1.000` / `2.000` 的比率标注；选中单个端点时色板置灰（端点没有可改的存储颜色）。
2. **应用参考线组后选项栏看不到状态。**
   `OptionsPanel::refresh()` 调了 `rebuildGroupRows()` 建立行，但**没有调用 `resized()`**；
   行的尺寸只在 `resized()` 里设置，而 JUCE 只在组件尺寸变化时才自动调用它——
   新建一个参考线组不改变选项栏尺寸，所以行停在 0×0。
   其他面板（`PresetPanel`、`InstrumentPanel`、`EditorPanel`）重建后都调了 `resized()`，
   只有这一处漏了。修法：重建后显式 `resized()`，并把分组区域可用高度钳制到非负。
3. **新增左键框选多个音符**（新功能，不是 bug）。空白处左键拖动出选框，
   **相交即选中**、边拖边更新、`Ctrl` 拖动与原有选择取并集；
   命中参考线 ±6 px 时仍优先写音符。为此给 `PianoGrid` 加了 `DragMode::marquee`
   与 `AppState::setSelectedNotes`（一次广播批量替换选择）。

针对这三个问题都补了测试：端点独立性 12 条断言、整八度 12 等分 14 条断言；
自检新增了「选项栏行尺寸必须大于 0」（bug 2 的直接回归）、
「点两端 → 12 等分 → 点叉点得到 1/12 的圆点」、「框选命中两个音符且第三个不受影响」、
「Ctrl 框选是并集」、「空框选清空选择」、「参考线附近按下仍然写音符」。

### 再修两个（第二轮试用反馈）

4. **线段顶点（两个端点圆点）没法改颜色。**
   之前把端点的色板开关置灰了，理由是端点没有可存储的颜色字段。用户要求能改，于是给
   `ReferenceGroup` 加了 `frameColourIndex`——两个端点是同一个音高类，共享一个颜色；
   应用参考组时，生成的参考线组里那条端点线也取这个颜色。预设与工程文件同步保存该字段。
5. **点击一个叉点会让同批其他叉点全部消失。**
   这是我自己实现里的真 bug：`OctaveLadder::changeListenerCallback` **忽略了 `source` 参数**，
   于是「把叉点变成圆点」这次**文档变更**也走进了「清除叉点」的分支。
   修法：只有来自 `AppState`（即选择变化）的广播才清空叉点；来自文档的变更只**剔除那些位置已经变成圆点的叉点**，
   这样既保住了同批其他叉点，也不会出现「叉点压在圆点上面」的状态。

第二条在自检里暴露得很干净——诊断输出显示 `selectedDots=2` 而点击的圆点是 0.25，
说明点击根本没进圆点分支：上一段 12 等分留下的 10 个叉点仍在，而其中恰好有一个在 0.25（3/12），
点击被叉点分支截走了。这反过来印证了第 5 条确实是产品 bug 而不只是测试写法问题。

补的测试：预设库往返多了一条 `frameColour` 断言；自检新增
「生成两个叉点 → 点掉一个 → 另一个仍在」（bug 5 的直接回归）与
「选中端点时色板可用」（bug 4 的直接回归）。

## 决策与发现

**设计决策**（已同步到 `../docs/01-requirements.md` 的 D28–D34）

- 线段恒为一个八度、端点不入存储；参考组只存比率，参考线组才绑定绝对频率。
- 叉点是临时预览层，由「改变选择」的动作清除；点击叉点变圆点**不**清同批其他叉点。
- 等分产生叉点而非直接产生圆点，可先看再挑。
- 预设存应用配置目录而不是工程文件，历史只保留本次会话。
- 多个参考线组可同时启用，各自带开关与删除。

**踩到的坑（两个都值得记住）**

1. **`dividePositions` 把整条线段折成了零长度**。最初我对两个端点做了八度折叠，
   而 `foldPosition(1.0) = 0.0`，于是「从 0 到 1」这个完整八度算出 span = 0，返回空数组，
   测试随即在 `thirds[0]` 上空指针崩溃（0xC0000005）。
   根因是把「位置」和「端点」混为一谈：两个端点是 **0 和 1**，不是一个类被折叠后的同一个值。
   修法：选中的区间按原样使用、只钳制到 `[0,1]`，不做折叠。
2. **三次「诡异的崩溃/挂起」其实是同一件事：改头文件后增量构建不重编**。
   现象是随机的（这次是访问违例、下次是死循环、位置各不相同），根因是
   **本机 MSVC 是中文版，`/showIncludes` 的前缀是「注意: 包含文件:」，CMake 在 936 代码页下
   把它解码成乱码**（`娉ㄦ剰: 鍖呭惈鏂囦欢:`），于是前缀永远匹配不上编译器输出，
   Ninja 的依赖文件是空的 —— **改头文件不会触发重编**，链接出来的程序按旧结构布局访问内存。
   试过 `VSLANG=1033`（无效，cl 仍输出中文）和显式钉死 CMake 的前缀变量（`project()`
   阶段已经写死，覆盖不掉）。

   最终处理：**构建脚本每次从零重建**（`build_app.bat` / `build_tests.bat` 里带路径守卫地
   删除自己的构建目录），并在 `docs/05-build-env.md` 记下这条。代价是每次约 80 秒，
   比反复追查随机崩溃划算得多。

   顺带把测试跑法改成了**每个测试组一个独立进程**（`NiDawTests.exe <组名>`，`--list` 列组名），
   这样一组挂起或崩溃不会吞掉其他组的结果；同时给测试进程装了崩溃处理器（写地址与模块基址）
   并关掉 Windows 错误对话框（否则崩溃后进程会被对话框挂住，看起来像死循环）。
