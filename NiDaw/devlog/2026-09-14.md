- 继承的记忆放在 `AppState`（会话级、不写工程）：它说的是「这一行近来是什么样」，
  和锁定状态那条（写工程）不是一回事。

## 第十八批·第三批：插件窗口尺寸（Kontakt 8 界面显示不全，已修复）

### 起因

用户反馈：用 Kontakt 8 时「窗口显示不全」——插件界面被切掉一部分。

### 原因

`PluginWindow` 是按「宿主先定窗口尺寸，插件挤进去」写的：

1. 打开时用的是 HM 自己的默认尺寸（640 × 420，或插件创建那一刻报的尺寸）；
2. 插件**之后**改自己界面尺寸时（Kontakt 加载音色库、点缩放按钮都会），窗口不跟，
   界面就长到窗口外面去了——这正是"显示不全"；
3. HM 还给插件界面强加了一个 JUCE 的右下角缩放柄（`editor->setResizable (true, true)`），
   那是宿主的活，而且盖在插件自己的角落控件上；
4. 窗口位置用 `centreWithSize`，当界面比屏幕可用区还大时会开成两半都在屏幕外。

### 修法（照 JUCE 自带 standalone 宿主的做法）

- **尺寸由插件说了算**：打开时取插件报的尺寸（并把它的 constrainer 最小尺寸当底线），
  再把窗口设成这个尺寸；不再用 HM 的默认窗口尺寸。
- **跟着插件变**：给插件界面挂 `ComponentListener`，它 `setSize` 就让窗口跟着 `setSize`
  （并用一个 `editorDrivesSize` 守卫切断回声，避免来回震荡）。
- **缩放权交回插件**：窗口的 `setResizable` 取 `AudioProcessorEditor::isResizable()`，
  不再替插件加角落缩放柄；窗口被拖动时用 `setBoundsConstrained` 交给插件的 constrainer 裁决，
  插件拒绝就把窗口弹回它实际定下的尺寸。
- **位置钳进显示器可用区**（照 JUCE standalone 的算法），避免开窗就跑到屏幕外。

### 验证

- 测试插件 `NiDaw/TestPlugin` 现在**带一个 900 × 600 的界面**（原来是通用参数面板），
  于是这条缺陷能被自动化抓到。自检新增 3 条：
  `the plugin's own size was read (900x600)`、
  `the window is at least as big as the interface (900x600 for 900x600)`、
  `the window follows a plugin that resizes itself (1200x320)`
  ——最后一条正是旧实现会失败的那条（旧代码不会跟，窗口停在 900 × 600）。
- 基线：单元测试 24 组 / 1808 条不变；离屏自检 **580 项**（原 577 项）。
- 交付物由 `work\make_release.bat` 重出。

## 第十八批·第一批：外部 VST3 乐器（已完成）

### 完成

- **第七种轨道：VST 乐器**（`TrackKind::vst`，序列化值 6）。＋ 菜单里多一项，选中后先弹
  **插件选择器**（搜索框 + 列表 + 重新扫描 / 添加目录 / 确定 / 取消），选好才建轨道；
  行头上的按钮在 VST 轨上叫「插件界面」，点开的是**插件自己的窗口**（非模态、可缩放、全局复用，
  没界面的插件用 JUCE 通用参数面板）。
- **插件扫描按需做**：打开选择器时若缓存为空才在后台扫描；结果缓存到
  `%APPDATA%\NiDaw\pluginlist.xml`，附加目录记在 `vstfolders.json`；启动不扫描、不阻塞。
- **音高按半音 + 音分交给插件**（用户选的）：音号 = `round(69 + 12·log2(f/440))`，
  剩下的音分用**该音符独占的 MIDI 通道**上的 pitch bend 补（14 位、±2 半音，实例就绪时给
  16 个通道发一次 RPN 0）。所以 660 Hz（1:3）这种不在半音上的频率也能按原频率发声。
- **插件状态内嵌工程**：保存前向活的实例取一次状态（base64）写进 `.nprj`，连路径 / 名字 /
  唯一 id 一起存；打开工程时按路径→唯一 id→名字的顺序找插件，找到就恢复状态。
- **缺插件回退**：轨道保留、静音，行头显示「（插件缺失）」，按「插件界面」说明缘由。
- **导出包含 VST 轨**：每个文件新建**私有离线实例**（按导出采样率 prepare + 恢复状态），
  所以分轨与总混音听感一致；实时监听的实例不参与导出。
- **测试用 VST3 乐器**：`NiDaw/TestPlugin/TestInstrument.cpp`（无界面，正弦，跟 pitch bend），
  由 `add_dependencies(NiDaw NiDawTestInstrument_All)` 随主程序一起构建，
  自检用它真跑「实例化 → 送 MIDI → 按导出渲染 → 测到 660 Hz → 状态存进工程再读回来」。
  它**不进交付物**，只用来测。
- 文档：`01-requirements.md` 需求 117–121 + 决策 D117–D123（并把「第三方插件宿主」从非目标里划掉）、
  `02-architecture.md` 加了 `PluginHost` 一节与新类型、`04-ui-spec.md` 加了选择器与插件窗口、
  `06-testing.md` 加了 `VstInstrument` 组 / 新自检项 / `--vst3` 参数与 6 条手工验收、
  `08-handoff.md` 更新基线与构建产物。

### 决策与发现

- **只做 VST3**：这份 JUCE 自带 VST3 SDK（`juce_audio_processors_headless/format_types/VST3_SDK`），
  不联网、不额外授权；VST2 的 SDK 既没随 JUCE 分发也不允许再分发，所以 VST2-only 的老插件不支持。
- **每音一个 MIDI 通道**是「半音 + 音分」的前提：一个通道上两个音就不能各自弯音，
  和弦就会互相带跑。代价是插件必须响应 16 个通道——Kontakt 要把乐器设成 Omni。
- **实例只在消息线程创建 / 释放、且活到 HM 退出**：音频线程可能正拿着它渲染，
  让消息线程始终持有最后一份引用是最省事的保证（删掉的轨道其插件留在内存里，退出才回收）。
- **插件加载失败只报告一次**。最初「描述找不到」也回调 `onInstrumentChanged`，
  回调里又重建调度、重建调度又去请求同一个插件——**栈溢出**（0xC00000FD）。
  现在失败的 (轨道, 插件) 组合记在 `TrackState` 里，不再重试。
- **自检参数解析改用 `getCommandLineParameterArray()`**（即 `CommandLineToArgvW`）。
  自己用 `StringArray::fromTokens` 解析那条命令行时，带引号的参数会让程序在进入自检前就崩
  （0xC0000005）；换成系统那一份解析器后三种引号写法都正常。
- **`juce_add_plugin` 的聚合目标是 `<name>_All`**，`add_dependencies(NiDaw NiDawTestInstrument)`
  只会构建 SharedCode（`HMTestInstrument.vst3` 目录是空的）。要依赖 `_All` 才会链接并拷贝出 bundle。
- **插件目标要显式声明 `JUCE_VST3_CAN_REPLACE_VST2=0`**，否则 JUCE 在编译 VST3 wrapper 时
  `#error`（那段检查是给「既发过 VST2 又发 VST3」的插件用的）。
