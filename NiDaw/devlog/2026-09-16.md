## 第二十三批：循环片段缩略图 + 音轨栏 / 编辑栏视图分离（已完成）

### 完成

- **循环片段的缩略图不再拉伸**：音轨栏里片段的音符缩略图改成从
  `music::expandClip`（引擎展开片段用的同一个函数）取内容，按 `像素/拍 ÷ 960` 的真刻度
  定位、裁到片段矩形。循环片段现在是「一个周期的内容按周期平铺」，与上方的重复分隔线、
  以及实际发声完全一致；拖动片段长度只会多出或少掉一整段，已有内容一个像素都不动。
  非循环片段行为不变（`expandClip` 对它就是一遍、只取窗口内的音符）；音频片段那条路径
  （`drawSampleThumbnail`）不动——音频片段在引擎里只放一次，现在按文件内容在真刻度上画是对的。
- **两栏各自一套横向视图**：`EditorViewState` 新增 `arrangementPixelsPerQuarter` /
  `arrangementHorizontalOffsetTicks`，与编辑栏原有的 `pixelsPerQuarter` /
  `horizontalOffsetTicks` 并列；新增 `TimelineView { arrangement, editor }` 与
  `pixelsPerQuarterFor / horizontalOffsetFor / setPixelsPerQuarterFor /
  setHorizontalOffsetFor / xForTimelineTick / timelineTickForX` 一组访问器，
  所有需要横向映射的组件都走它。归属：`TrackArea` 自己 + 它的 `TimelineRuler` /
  `TempoMarkerTrack` 用 arrangement，`PianoGrid` 与编辑栏那两根用 editor
  （两条标尺 / 标记轨的构造函数多一个 `TimelineView` 参数，默认 `editor`，所以编辑栏那边不用改）。
- 音轨栏的滚轮平移、`Alt`+滚轮缩放、拖动到边缘时的自动滚动都只改 arrangement；
  编辑栏的滚动条 / 滚轮 / 自动滚动 / `定位音符` 只改 editor。两栏都随工程保存。
- 自检钩子：`TrackArea::getClipThumbnailRectsForTest()`（画笔将要画的音符条，**同一条代码路径**）、
  `TimelineRuler::getXForTickForTest()`、`TrackArea::getRuler()`。

### 决策与发现

- **画面必须和声音同源**：缩略图以前用「`整宽 ÷ min(循环长度, 片段长度)`」把**一个周期拉伸
  铺满整个片段**（注释还写着「one repeated period is enough to read the contents」）。
  这在循环片段上既和旁边按真刻度画的重复分隔线对不上，又会在拖动长度时一路改变拉伸比例——
  用户看到的「改变事件长度时缩略图不正常」。改成复用引擎的 `expandClip` 之后，
  「画面 = 声音 = 分隔线」是构造上保证的，不需要再维护第二套平铺公式。
- **刻度对齐只是「栏内」的要求**：原来两栏共用 `pixelsPerQuarter` / `horizontalOffsetTicks`，
  `docs/02-architecture.md` 还把「两边天然对齐、滚动与缩放联动」写成不变量。用户要的是
  **分开**（明确说不需要一起滚动缩放），所以把不变量降级成「栏内对齐」，栏间各自独立。
- **旧工程要看起来一样**：读盘时如果文件里没有 `arrangement*` 两个字段，就用编辑栏的值
  播种音轨栏，这样老工程打开时两栏仍然重合，之后才各自独立。
- 踩到一条既有兜底：`projectFromJson` 里「没有 `tracks` 字段的文件整体退化成新工程」
  （`p = makeDefaultProject()`）会**连带丢掉 view**。手写 JSON 的测试必须带上
  `"tracks": []`，否则测的其实是「新工程默认值」——第一版旧文件测试就是这么红的。

### 验证

基线（旧值 → 新值）：单元测试 **27 组 / 1906 条 → 27 组 / 1918 条**，
离屏自检 **644 项 → 655 项**（快照仍然是 38 张，这一批不加图）。

- 单元测试：`Serialization` 补两条——两栏视图各自往返（220/480 与 90/1920 都对得上，
  并检查访问器取的确实是要求的那一份）、旧工程缺 `arrangement*` 时用编辑栏播种。
  `Clips` 组的 `expandClip` 平铺 / 裁切断言本来就齐（「looping tiles the content」
  已经断言 4 次重复与首尾 tick），没有再补。
- 离屏自检新增一节「音轨栏与编辑栏各自平移缩放，缩略图按真刻度平铺」（11 项）：
  1 小节循环、总长 4 小节的片段画出 **4 份**、彼此正好隔一个周期、每一份都落在分隔线上；
  拉长到 5 小节后**前 4 份逐字段相等**；编辑栏缩放时音轨栏片段 x 不变，
  音轨栏平移时编辑栏音符 x 不变，而音轨栏的标尺与片段仍然共用一套映射。

## 第二十四批：插件是「一直活着的乐器」（用户反馈修复，已完成）

### 反馈

用户反馈两件事：「我无法使用插件自带的键盘试听音色」和「有时候插件窗口仍然不完整」。

### 找到的原因（一）：宿主只在自己发过音时才处理插件

`AudioEngine::renderVoices` 里对 VST 轨有这么一句短路：

```cpp
    if (! info.instrument->isActive())
        continue;                       // ← 插件根本不会被 processBlock
```

而 `HostedPlugin::isActive()` 问的是 **HM 自己的通道分配表**（`channels.activeCount() > 0
|| tailSamplesLeft > 0`），也就是「HM 发过音、而且还没放完」。可插件**自带的键盘**、
它自己的琶音器、内部音序器，全都是**插件内部**发声、宿主一个音符都没发——于是这些声音
从来没被渲染过。

更彻底的是**停止状态**：`renderNextBlock` 在没播放时只渲染内置乐器的试听声部
（`renderPreviewVoices`），VST 轨压根不参与；唯一沾边的 `else if (lastMatched != nullptr)`
还得是「跑过一次之后」才成立（`lastMatched` 由播放分支里的 `matchTracks` 赋值）。
所以「不按播放就用插件键盘试听」在两个方向上都不可能出声。

### 找到的原因（二）：界面尺寸是创建时的快照，而且回推期间不记录

`PluginWindow::Content` 里有一份 `preferredSize`（创建时抓一次）与一份 `editorNativeSize`，
窗口用前者、滚动判断用后者；而监听器在 `editorDrivesSize`（宿主正在改窗口尺寸）时
**直接 return**——连「插件现在到底多大」都没记下来。记录值和界面真实尺寸一旦脱节，
「窗口该多大」「要不要滚动」都会按错的值算，表现就是有时候窗口比界面小、还没有滚动条。

### 修法

- **插件按「一直活着的乐器」处理**：`renderVoices` 去掉 hosted instrument 的 `isActive()`
  短路（每块都调 `renderAdding`，走带跑不跑都一样）；`renderNextBlock` 的停止分支改成
  「`getScheduleSnapshot()` → `matchTracks()` → `renderVoices()`」，于是**没按过播放**
  也能出声（顺带让释放尾音照旧收尾）。内置乐器仍然按 `isActive()` 走——它们的试听由
  `renderPreviewVoices` 负责，这条改动只针对外部插件。
- **开窗时把键盘焦点交给插件界面**：创建后 `setWantsKeyboardFocus (true)` + `grabKeyboardFocus()`，
  插件自带键盘常靠电脑键盘演奏。
- **窗口尺寸以界面当前真实尺寸为准**：删掉 `preferredSize`（`getPreferredSize()` 直接返回
  `editorNativeSize`），`layoutEditor` 排完之后**回读**一次，监听器里**无条件记录**新尺寸，
  只有「要不要跟着改窗口」才受 `editorDrivesSize` / `scrolling` 限制。

### 验证

基线（旧值 → 新值）：单元测试 **27 组 / 1918 条 → 27 组 / 1922 条**，
离屏自检 **655 项 → 658 项**（快照仍然是 38 张）。

- 单元测试新增两条（用 `CountingInstrument` 假乐器，这是唯一能覆盖「插件自己发声」的办法）：
  `an idle external instrument is still processed`（`active = false` 时仍被渲染、输出进总输出）、
  `a plugin can be auditioned while the transport is stopped`（**第一块**、从未按过播放时就被渲染
  且有声音）。修之前这两条都会因为 `renderCalls == 0` 而失败。
- 离屏自检新增三项：界面尺寸记录跟着插件走（1200×320、400×300 都记录对）、
  界面能拿到键盘焦点。
- 交付物由 `work\make_release.bat` 重出。

### 留下的已知边界

「窗口仍然不完整」还有一种可能是**屏幕本身装不下插件**（这时窗口会停在屏幕大小、界面里出现
滚动条，用滚轮或拖滚动条就能看到其余部分），以及个别插件**只报小尺寸、从不自己长大**。
前者是设计好的行为，后者宿主无从判断——用户如果还遇到，请说明是哪个插件、缺的是哪一块
（右 / 下 / 整窗偏小）、有没有出现滚动条。

### 踩坑与发现

- **`inline` 函数不能只在一个 TU 里定义**：`run()` 原来是 `inline`，搬到 `SelfTest.cpp`
  之后链接报 `LNK2019`（`Main.cpp` 只有声明、定义没有发出符号），去掉 `inline` 即可。
- **构建脚本「绿着红」**：`cmake --build` 在 `vs_link_exe` 失败时返回的是 **-1**
  （`[code=4294967295]`），而 `if errorlevel 1` 把 -1 当成成功——脚本打印了 `BUILD_OK`
  却没有 exe。两个构建脚本现在**同时看退出码与日志**（`ninja: build stopped` / `: error ` /
  `fatal error` / `FAILED:` 任一命中即失败）。
- **拆测试类时不能用 `Trim()` 找类的结尾**：类内部的 lambda / 结构体以缩进的 `};` 结尾，
  只有**列 0** 的 `};` 才是类的结尾（第一版按 `Trim()` 切，四个文件都少了一个右花括号）。
- **夹在测试类之间的辅助类型会被漏掉**：脚本只搬「`class X : public juce::UnitTest`」的块，
  `CountingInstrument` / `FakeEffect` 这种夹缝里的类型必须显式收进共享头。
