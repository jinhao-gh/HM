# 2026-09-18

## 第三十五批：马尔科夫链生成器（重做生成器部件，已完成）

用户对上一批的模块补丁生成器给出了重做要求：**要马尔科夫链**——单位是节点、连线是带权重的转移、
可以多条子链并行、单位可以是自定义内容或随机内容（旋律 / 和声）、随机内容每次激活都不一样、
可以指定节奏或指定音高；并且中途追加了一条：**激活一个单位时，与它并行连接的单位也同时被激活**。

### 做了什么

- **换掉了整个生成器**：删掉 `Core/Patch.*`、`Core/PatchStore.*`、`UI/PatchCanvas.*`、
  `UI/PatchWindow.*`、`Tests/PatchTests.cpp` 与它们的两张快照；新的链生成器接手顶栏「生成器…」与 `G`。
  `Core/Generator.*`（材料）改名 `Core/Material.{h,cpp}`，它仍是「锁定参考线 → 槽位表」那件事。
- **核心 `Core/Chain.{h,cpp}`（两个目标都编译、可单测）**：
  - 单位（`Unit`）绑定一条**轨道**当乐器，带长度（0.5–32 拍）、位置、内容类型；
  - **转移**（`Edge`）带权重，箭头显示**归一化后的概率**，允许自环；没有出边则这条子链停下；
  - **并行连接**（`ParallelLink`）是第二类连线：激活一个单位时，与它并行相连的单位**同时**被激活，
    并且沿并行边传递（A‖B‖C 三个一起响）；每个单位在一次激活里只响一次，所以环也不会无限展开；
    **并行不改变巡游者下一步走到哪**；
  - **子链**（`Walker`）是并行的巡游者，共用同一张图，各自从自己的起点出发；
  - 内容：自定义内容逐次原样重放；随机内容分**旋律**（每次一个音）与**和声**（同时一簇，最多 6 个），
    节奏可随机（密度掷骰）或**手写步格**，音高可随机（从锁定参考线的槽位里取）或**手写音高表**
    （旋律按序循环、和声整簇同时响）；鼓轨单位用 12 个鼓垫；
  - **每次激活的种子** = hash(链种子, 遍号, 子链, 单位, 第几次激活)：每次激活都不同、每次重放都不同，
    而同种子 + 同遍号逐字段可复现（这是自检能断言「同一遍一样、不同遍不一样」的前提）。
- **引擎：生成器有自己的走带**。`PlaybackEngine` 多了一条监视通道（自己的位置、自己的游标、
  自己的音符 id 空间、只释放生成器自己的音符），两条事件流在同一个采样级切块循环里跑；
  `buildMonitorSchedule` 让生成器的音符走各轨自己的音色 / 效果器 / 推子；导出完全不受影响。
- **界面**：`UI/ChainCanvas`（单位盒子、两条端口各自成类、转移箭头带百分比、自环、并行连接的加倍线、
  拖拽建线、右键删线、悬停说明、子链彩色环）、`UI/ChainWindow`（按轨道加单位、子链面板、
  权重视察器、**演奏条**、状态行、播放 / 停止 / 回到起点 / 跟工程一起走带 / ● 录制）、
  `UI/UnitBar`（**单位编辑栏**：名字 / 乐器 / 内容 / 长度 / 返回工程；随机内容的参数行、
  手写步格、手写音高表；随机单位的画布只读）。
- **录制**：按 ● 录制 → 走一段 → 停止时，每个涉及的轨道各得一个片段（名 `生成 N`，
  起点＝按下录制那一刻的播放头），音符就是听到的那些；**整次录制是一条 `applyEdit`**，
  一次 Ctrl+Z 全部还原。

### 决策与发现

- **并行连接与转移是两种关系**（用户追加的需求）：转移决定「下一个是谁」，并行决定「和谁同时响」。
  分开实现是唯一能同时说清两者的做法——把并行也做成带权重的边，用户就没法表达「永远一起」。
- **`Path::getNearestPoint` 的坑**（第三十四批记录）在这一批的画布上同样适用：拖拽命中测试用的是
  「取回最近点再量距离」，不是它的返回值。
- **一条断言写错不算 bug，一条行为写错才算**：这一轮自检里「新单位自带自环」与「两根出路的概率是分掉的」
  两条失败，查下来都是**我的期望写错了**（第一个单位按设计是成为子链起点，自环要靠拖拽），
  于是改了断言并把自环用真实拖拽补上；而「和声根音落在材料最高处时只出一个音」是**真的行为缺陷**，
  改成「上面没有就向下取」，并加了单测。
- **未做**（留给下一批）：生成器自己的 BPM（现在沿用工程速度，所以录音正好落在网格上）、
  并行连接的概率、把一遍演奏存成链的变体、单位级效果器、槽位键盘。
