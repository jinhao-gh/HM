## 第三十七批修正：混音台推子/按钮点不动 + 左右两条电平表 + 刻度

用户用过混音台之后报了三件事：

1. **「推子和按钮无法交互」**——条带上的推子、声相、M / S、效果器行、乐器入口全都没反应；
2. 要**看到左右两个声道各自的音量**；
3. 要为**推子和电平表标注刻度**。

### 推子为什么点不动

第一版把条带**画在混音台的内容组件上**（`Content::paint` 里手绘），命中测试也是手写的
（`Content::mouseDown` 里拿坐标去比 `StripLayout`），而条带区上面盖着一个 `Viewport`——
**它把条带区的每一次点击都吃掉了**，事件根本到不了 `Content::mouseDown`。
于是只有 master 条（在 viewport 之外）和底部走带按钮能点，轨道条带一根都点不动。

更糟的是：自检当时用的是 `clickStripForTest` / `dragFaderForTest` 这类**直达内部函数**的捷径，
它们绕过了整条鼠标路径——所以 41 张快照与 857 项断言全绿，用户一上手就发现是坏的。

修法：**每根条带改成真实的组件**（`MixerWindow::Strip`，装在 `Viewport` 里的普通容器里）。
它自己画自己、自己收鼠标（按下 / 拖动 / 松开 / 右键菜单 / 滚轮），滚动与裁切回到 JUCE 手里，
画的和点的是同一份 bounds，不可能再错位。

自检也跟着**改了性质**：不再用捷径，而是

- `content->getComponentAt (推子中间那个点) == 条带自己`（这一条就能抓住「被容器吃掉」）；
- 把**真实的**按下 / 拖动 / 松开事件发给条带组件，再断言工程里的音量 / 声像 / M / S 真的变了，
  而且拖动记成**一条**撤销（`getUndoDescription() == "轨道音量"`）。

### 左右两条电平表

引擎原来是「一个轨道一条峰值」（取两声道里大的那个）。现在按声道上报：
`PlaybackEngine::MeterReading { peakLeft, peakRight, clipLeft, clipRight }`，
`mixTrackIntoOutput` 在推子与声像之后**左右各量一次**，`renderNextBlock` 结尾同样按声道量总输出；
读一次即清。条带上就是**两根 12 px 的竖条**，各有自己的峰值保持横线与削顶红条。
单测补了「声像硬左时右声道为 0」，自检补了「播放中点条两根都有读数」与
「把声像拖到最左 → 右边那条落下去而左边还在」。

（这里踩了一个小坑：第一版自检的 `renderAndTick` 在一个循环里渲染 60 块但**只 tick 一次**，
于是右声道那条"只落 0.67 dB"，看起来像左右没分开。改成每块都 tick 才测到真东西。）

### 刻度

- **推子**：左边一栏画 `+6 / 0 / -12 / -24 / -40 / -60` 的刻度与数字（dB 线性，间距相等），
  0 dB 处还有一条横贯推子的细线；推子下面的数字就是当前读数。
- **电平表**：右边一栏画 `0 / -12 / -40` 的数字（另有 -6 / -60 的刻度线）。
  电平表是按**幅度**线性画的，所以刻度越往下越密——0 dB 在顶、-6 dB 正好在一半。
- 自检直接问这两套刻度的像素位置：+6 必须在推子顶端、-60 在底端、0 在中间；
  电平表的 -6 dB 必须在条的正中间。

条带因此从 92 px 加宽到 **106 px**（要放得下刻度栏）；窗口太矮时条带保持自己的高度、
由滚动条去够，不再把推子压扁。

### 数字

- 单元测试 **29 组 / 2039 → 2045 条**（`Playback` 的电平表断言按声道重写并补了 6 条）。
- 离屏自检 **857 → 866 项**，快照仍 **41 张**（`40-mixer.png` / `41-mixer-playing.png` 重拍，
  里面现在有左右两条表和刻度）。

## 追加：推子更窄、电平表更宽且带颜色、插件行加旁通按钮

用户看过之后提了两件事：**「请把推子做窄一点，电平表做宽一点并附带颜色变化」**、
**「请为插件栏附加旁通按钮」**。

- **比例**：推子轨道 26 → **15 px**，两根电平表各 12 → **18 px**（条带总宽仍 106 px，
  推子旋钮也从「轨道 ±3」收到「±2」）。演奏时要看的是表，不是推子的宽度。
- **颜色**：电平表改成**按刻度着色**——一份色标（-60 深绿 / -24 绿 / -12 黄绿 / -6 黄 /
  -3 橙 / 0 红）同时驱动 `ColourGradient` 的填充和 `MixerWindow::getMeterColourForTest`，
  所以自检问的就是画出来的那一个函数。颜色属于**刻度**而不是属于电平：同一个高度永远同一种颜色，
  电平高起来只是盖到更多颜色（电平表的通用做法，也不会被上一块的音量骗到）。
  刻度线改成画在填充之上的半透明黑，横线（峰值保持）仍在最上面。
- **旁通按钮**：插入链每行**右端 18 px** 变成按钮——在链上是亮色方块，旁路后变暗并画一道斜杠；
  **点它切旁路**（一条撤销，`旁路效果器`），行的其余部分照旧打开插件界面，
  右键菜单也补了「旁路」（第 4 项，带勾）。效果器窗口里的「开 / 旁」与它是同一件事。

  （原来这颗圆点只是**画出来但点不动**的装饰——用户说的「附加旁通按钮」就是这个。）

### 数字

- 离屏自检 **866 → 873 项**（旁通 4 项、颜色 2 项、宽度关系 1 项），快照仍 41 张；
  单元测试不动（2045 条）。

## 追加：单选一个音符时比率那一行不显示（真 bug）

用户报：**「点击单个音符时比率选择没有显示，选中多个音符时反而显示出来了」**。

可见性判断本身一直是对的（`ratioRowVisible()`：有音符选中且不是鼓轨就是 true），
所以先加了一行临时诊断把布局打出来：

```
DIAG bar height=62 rowOnScreen=1 rowBounds=0 0 0 0 targetVisible=1 targetBounds=0 0 0 0
DIAG key 0 bounds=0 0 0 0 visible=1 enabled=1
... 五个键全是 0 0 0 0
```

**行「可见」，但被排成了零尺寸** —— 所以画面上什么都没有。

根因是**布局时机**，不是可见性：

- 第二十六批把音符编辑栏做成**固定槽位**（`slotHeight = 62`），为的是选中数变化时画布不许
  抖动（D140）。于是「没选中」和「选中一个音符」两种状态下，这个栏的 **bounds 一模一样**。
- 而 JUCE 只在组件的 **bounds 变化**时才要求它重新布局。没选中时 `NoteEditBar::resized()`
  给比率行安排的是空矩形；点上一个音符之后 `refresh()` 把行设成可见，但**没有人再排一次版**，
  它就一直是那个零尺寸矩形。
- 多选时条带会长高（多出逐音符列表那一段），bounds 一变，`resized()` 被执行，
  行就有了 51 px —— 这就是「多选反而显示」的怪现象。

修法：`NoteEditBar::refresh()` 结尾**自己再调一次 `resized()`**。栏内的子控件排布本来就是
幂等的，几行 `setBounds` 而已。

自检补了 3 条**真尺寸**断言（行高 ≥ 18 px、目标频率读数有尺寸、五个键都有宽高）。
原来那批断言只看了 `isVisible()` 与 `getBaseHeight()`——**"可见"和"画得出来"是两件事**，
这次的教训就记在这里。
