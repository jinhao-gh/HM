# 2026-09-22

## 第三十八批：编辑栏底部的控制器栏（力度竖条 + 可画的 CC 折线）

用户要求「像 Cubase 那样能在编辑栏下部改力度 / 表情 / 踏板等 CC 信号的界面，
表情、踏板等 CC 以可绘制的折线显示，这一栏可被折叠」。问清了三件事之后开工：
CC 要**真的响**（VST 全量 + 内置认表情与踏板）、力度用 **Cubase 式竖条**、
曲线跟音符一样**住在片段里**。

### 做了什么

- **数据**：`Clip::controllerCurves`（`ControllerCurve` = CC 号 + 折点表，折点是
  「clip 相对的 tick + 0..127」）。`Core/ControllerMath.h` 是唯一编辑它们的地方：
  取值（点之间线性插值，两端各自保持）、插入 / 同 tick 覆盖 / 删除 / 钳制、
  `expandControllers`（按片段窗口裁切、按 `loopLengthTicks` 平铺、在折点之间按 **1/16 拍**
  插出中间值，**值没变就不发事件**）。写进 `.nprj` 的 `controllers` 段；旧工程没有这一段就是空。
- **引擎**：`buildSchedule` 把曲线换成 `TrackRenderInfo::controllers`（绝对秒），
  `PlaybackEngine::processControllers` 在每个块开头处理——**排在音符之前**，
  这样正好压在音符结尾上的踏板事件仍然生效。有外部插件的轨道只转发
  `HostedInstrument::sendController`（发给当前有音符的通道，没有就发 1 号通道）；
  内置乐器由引擎自己处理：CC11 折成该槽的 `expression` 乘数（在 `mixTrackIntoOutput`
  里和推子同一处乘下去，所以混音台的表也跟着掉），CC64 踩下时把 note-off 存进
  `sustainedNotes`、抬起时补发，跳转 / 停止 / 循环回卷先放掉。
  **两条路互斥**——有插件的轨道引擎一概不碰，绝不让表情或踏板被应用两次。
- **界面**：`Source/UI/ControllerLane.{h,cpp}`，编辑器最底部，横向与画布同一套映射
  （含钢琴模式的键盘缩进与右侧滚动条），所以同一 tick 在两边是同一条竖线。
  力度模式：每个实际发声的音符一根竖条（含循环重复出来的），上下拖动改力度（3 px 一格），
  多选时整组一起走，一次手势一条撤销。CC 模式：折线 + 折点，空白按住拖动 = 铅笔、
  拖折点 = 移动、右键折点 = 删、**Shift 拖动 = 两点之间画一条直线**、右键空白 = 清空这条曲线。
  标题行有信号下拉（常用 6 条 + 更多一批 + 自定义，自定义里 6/38/100/101/123 被拒绝——
  那是宿主自己发的 RPN 与 all-notes-off）。
- **可拖可折**：`PanelResizer` 加了竖向取向、`PanelToggleButton` 加了「底部栏」取向
  （默认高 110 px、往上拖变高、折叠成 18 px 细栏），高度与折叠状态存进
  `EditorViewState::controllerLane`（复用 `PanelSize`，旧工程缺字段 → 默认高度、展开）。

### 踩到的坑

- **命名撞车**：计划里数据结构和 UI 组件都叫 `ControllerLane`，同一个 `nidaw` 命名空间里
  编译不过。最后**数据叫 `ControllerCurve`**（它本来就是一条曲线）、UI 组件保留
  `ControllerLane`（它就是那条栏）。计划里的文件名 `Source/UI/ControllerLane.{h,cpp}` 不变。
- **我自己把 `Core/Types.h` 写坏了**，而且没有 git 可以还原：我用
  `(Get-Content) -replace … | Set-Content -NoNewline` 做批量改名，`-NoNewline` 把整个文件
  拼成了一行（于是第一个 `//` 注释把后面全吃掉了）。文件里**没有一个字节内容丢失**，
  缺的是换行。恢复办法：把那一行的内容按 token 重新排版成完整的 `Types.h`（内容逐条对照
  当时打印出来的整份文本），然后**全量重建**验证——所有翻译单元都编过、零警告，
  说明重建是完整的。教训写在这里：**不要用 shell 改源码文件**，改名一律走 review 过的补丁。
- **既有自检被布局变化撞了一下**：控制器栏占了编辑栏底部 116 px，画布从 264 变成 148 px，
  于是「框选」那两条既有断言把起点落在了**参考线**上（音符的八度族在更矮的画布里更密，
  点到线上就不是框选而是写音符了）。修法是让测试的两条带子的角落在**两条八度线正中间**
  （`110·2^4.5`、`110·2^3.5` 这种写法，无论画布多高都离最近的线最远），
  这样「框选」与「点线写音符」两件事就彻底分开了。
- **延音踏板的自检一开始失败**：不是引擎的问题——是我画的踏板曲线是**从 127 斜降到 0 的斜坡**，
  曲线在两点之间是插值的，于是它在音符结尾之前就跌破了 64，踏板自己先松开了。
  改成「127 保持到抬起前一 tick、然后归零」的一次阶跃就对了。这也说明曲线真的是插值播放的。

## 修正：左右移动编辑栏时控制器栏显示不正常

用户报「左右移动编辑栏时，控制器栏显示不正常」。原因是**重画范围**抄错了对象：
控制器栏的 `refreshPlayhead()` 只重画播放头附近那一条窄带（那是**画布**的做法，因为画布自己
就是移动视图的那个人），可控制器栏是**跟着视图走**的——于是拖动编辑栏的滚动条 / 滚轮时，
画布与标尺都动了，控制器栏的内容却停在原地。

上面那条标尺与标记轨为什么没事？因为它们俩的 `refreshPlayhead()` 本来就是**整条重画**
（代码里写着「短条，全刷比追踪脏列便宜」）。控制器栏也是一条短条，于是改成同一件事：
整条 `repaint()`，并加一个 `viewRefreshes` 计数给自检用。

自检补两条：把编辑栏右移一拍（`horizontalOffsetTicks = 960`）后
1. 第二个音符的竖条**正好落在第一个音符原来的 x 减 140 px**（= `pixelsPerQuarter`），
   也就是这一栏的内容真的跟着视图走了；
2. `getViewRefreshesForTest()` 增长，说明它确实走了面板那趟「跟着视图走」的定时刷新。

（这一条也提醒：**跟着别人动的组件要整条重画**，只有驱动视图的那个组件才配按脏区刷。）

数字：单元测试不变（30 组 / 2114 条），离屏自检 **914 → 916 项**，快照仍 43 张。

## 修正二：编辑栏里的「红线」与循环时的电平

用户报「有时编辑栏会莫名多出几条红线；循环的时候音符播放不正常」。两条都是真 bug：

### 红线：钢琴窗模式下键盘列被减了两次

控制器栏跟着画布的横向映射走，而画布在**钢琴窗模式**里左边留出 44 px 的键盘列。
面板已经按这个宽度裁过控制器栏一次，可 `ControllerLane` 的 `xForTick()` 里又减了一遍
`plotInset` —— 于是它的内容（竖条、折线、**播放头那条红线**）比画布**左移了 88 px**。
画布一条红线、标尺一个红旗、控制器栏一条红线，本来应该叠在同一列；错位之后就变成
「编辑栏里凭空多出几条红线」。

修法：控制器栏和标尺 / 标记轨一样，**只让面板裁一次**，它自己的 `xForTick` 就是画布那一套，
不再加减任何东西（`setPlotInset` 一并删掉）。自检补两条：参考线模式与钢琴窗模式下，
控制器栏的播放头 x 与画布的**逐像素相等**（216.0 / 216.0 与 260.0 / 260.0）。

### 循环：这一遍还没发出的 CC 沿用了上一遍的值

引擎把画出来的 CC 做成事件流，播放时按时间往前走。循环回到开头（或跳转）时，原来的做法是
「把游标退回上一个事件、再重放一遍」——可如果**循环区间之内根本没有 CC 事件**（曲线画在
循环的后半段、或者画在循环之外），就一个事件也重放不到，**表情与踏板会一直停在上一遍结尾
的值上**。曲线收在 0 的时候，第二遍的开头整段都是静音 —— 这就是「循环的时候音符播放不正常」。

修法：`rewindControllerCursors()`（循环回卷与跳转共用）先把该轨的 `expression` 清回 1.0、
踏板抬起，再按曲线重放 —— 语义变成「**这一遍还没发出的 CC 用默认值**」，与「折线只画到哪
就从哪开始算」的观感一致。

自检（单测）补了一条能抓住它的用例：一个 1 秒循环、两个音符，CC11 只有一个折点
（在循环**中间**、值为 0）。第一遍开头与第二遍开头同一窗口的峰值必须相同。
**把修正去掉这条会红**：第二遍是 `0`，第一遍是 `0.0368`。

### 顺带说一句踩到的老坑

改完 `ControllerLane.h`（删掉一个成员）之后我先用增量构建试自检，结果**崩在 `PianoGrid`

这已经是第三次栽在同一件事上：**动了头文件就跑全量重建**，不要心存侥幸。

快照仍 43 张，两个目标全量重建零 `\Source\` 警告。

## 修正三：跨越循环右边界的音符一直响

用户报「循环时接触到循环右边界的音符会被一直演奏」。

音符的 note-off 落在**循环区间之外**时，事件流永远走不到它（每一遍都在它之前回卷），
所以唯一能结束这个音的就是**回卷时那次"放掉所有声部"**。那份名单里写着 FM、采样器、
外部插件——**漏了减法、波表、鼓机三个池子**。于是那三类轨道上，这类音符每遍被重新触发
同一个声部、永远不会停 ✗。跳转（`applyPendingRequests`）那条路也漏了波表与鼓机。

修法：把"放掉所有声部"收成一个 `releaseAllVoices (immediately)`，五种池子一个不漏，
回卷与跳转共用同一份名单（这正是"同一件事写两遍就会漏一处"的典型）。

自检（单测）补了一条：一条**跨越循环右边界**的**减法合成器**音符，回卷之后电平必须落下去。
第一次尝试用"声部数"当判据，**没有抓住**——因为每遍回卷后重新触发的是**同一个 note id**，
声部被复用、数量一直是 1。换成**电平**才对：回卷后 0.15–0.35 秒的峰值必须低于回卷前峰值的
七成（释放 0.3 秒，衰减到一半以下）。
**把漏掉的三个池子去掉，这条会红**：`0.0816` 对阈值 `0.0680` ✓。

数字：单元测试 **2116 → 2118 条**（Playback +2），离屏自检仍 **918 项**、快照仍 43 张，
两个目标全量重建零 `\Source\` 警告。
