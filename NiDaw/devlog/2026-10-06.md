# 2026-10-06

## 第四十七批：MIDI 输入的力度 / 踏板 / 表情 + 虚拟键盘 + 琶音器（已完成）

用户一口气要了三件事：「请使软件 MIDI 输入可以读取按键力度、延音踏板、表情踏板等。请为软件增添
像 Cubase 一样的虚拟键盘。请为 MIDI 输入添加 arp 功能，可以选择速率、方向、八度等。」

三轮问答定下来的口径（都写进了 `01-requirements.md` 的 D195–D199）：

- **虚拟键盘是独立窗口**（顶栏按钮 + `Alt+K`），弹出来的音**与硬件 MIDI 键盘完全同一条路**。
- **琶音只作用于实时输入，录制录下琶音后的音符**（"听到什么就录什么"）；控件**两个窗口都放**。
- **走带停着也要能琶音**（它自己的时钟），**电脑键盘也能弹**（要焦点分家）。
- 「读取」的范围：力度 + `CC64` + `CC11` + `CC1`；踏板 / 表情**录进片段的控制器曲线**。
- 琶音参数：速率 + 方向 + 八度 + **Gate** + **Hold** + **Swing** + **力度模式**。

### 一、键盘的数据：力度、踏板、表情

三个缺口，都在「消息进来之后到乐器之间」这一段：

1. **力度**：`handleMidiMessage` 收到的力度本来就一路带到 `noteOnTrack`，但录音那一步写死了
   `note.velocity = 100`——现在 `PendingRecord` 存下按下时的力度，写进片段的就是它。
2. **控制器压根没人管**：`handleMidiMessage` 除了 note on/off 与 CC123 之外一律 `return`，
   所以硬件踏板在这套软件里**什么也不做**。现在三个控制器按当前选中轨送去引擎。
3. **实时音符不受踏板管**：引擎的踏板只拦 `triggerEvent`（调度出来的音符）的 note-off，
   而手弹的音符走 `applyLiveEvent`，直通乐器——修完第 2 条如果不一起修这里，就会变成
   「画出来的踏板有用、弹出来的没用」。

改法是把「控制器怎么响」收进一处：`LiveEvent` 由 `{..., isNoteOn, ...}` 扩成带类型的记录
（`LiveEventKind { noteOn, noteOff, controller }`），`processControllers`（画出来的曲线）与
`applyLiveEvent`（手弹的）都调同一个 `applyControllerToSlot`：

- 有外部插件的轨：只 `HostedInstrument::sendController`，引擎**不重复**处理；
- 内置轨：`CC11` 乘在这条轨的输出上（混音台表跟着掉），`CC64` 记成踏板状态；
- `applyLiveEvent` 里的 note-off 也过踏板判定（进 `sustainedNotes`，抬起时由
  `applyControllerToSlot` 补发）；
- `CC1` 只对 VST 有意义（内置乐器没有可接的东西），其它 CC 一样转发。

录制那一侧的规则是**一个控制器一次手势一条撤销**：第一次变化 `beginEdit("录制控制器")`，
之后的每一次只 `applyDerivedEdit` 写入；安静 300 ms（或录制结束 / 走带停下）之后再变就开新的
一条。这样"推一次表情踏板"是一条 `Ctrl+Z`，而不是一百条。

**踩过的坑**：写自检时发现两个控制器事件总是并成**一个点**——`recordTickNow()` 会把 tick
**吸附到网格**（和写音符的起点同一条规则），所以同一拍里的两次变化落在同一个 tick 上。
测试里的位置因此改成**一拍一个**；顺带也看清了这个行为的含义：录进片段的踏板是"量化到拍"的。

### 二、虚拟键盘

新窗口 `Source/UI/VirtualKeyboardWindow.{h,cpp}`，用 `juce::MidiKeyboardComponent`
（`SynthEditor` 的试听键盘早就用它），所以鼠标点、按住拖动、电脑键盘、按下高亮这几件事都是
JUCE 现成的；我们只负责把它接到**应用那条路上**：

```
鼠标点键 / 电脑键盘 / 硬件 MIDI
        └──► MainComponent::handleLiveNoteOn / handleLiveNoteOff
                 ├── 映射（或钢琴窗模式的十二平均律）
                 ├── 琶音（开着时按键不直接发声）
                 ├── 录制（一个音一条 录制 MIDI）
                 ├── MIDI 输入窗口的锚点学习
                 └── 两个窗口的高亮
```

几个具体决定：

- **18 px 一个白键**：52 个白键正好塞进 980 px 的窗口，**88 键一次看全**。一开始用了 22 px，
  结果 JUCE 的 `resized()` 会把 `firstKey` 拽回去（它不让最后一键滚出视野），"八度按钮挪可见
  范围"这件事在默认窗口里根本没发生——干脆把键盘做成一次看全，八度按钮只管**电脑键盘的起点**
  （这条也是自检里"看到 35 → 35"抓出来的）。
- **键位表写一份**：窗口上画的那行提示与真的能弹的键来自同一张 `kTypingKeys` 表
  （下排 `Z S X D C V G B H N J M`，上排 `Q 2 W 3 E R 5 T 6 Y 7 U`，`-` / `=` 换八度）。
  两份表迟早会漂。
- **硬件弹的音也亮**：`setKeysDown` 把"这些键是按着的"推进键盘状态；`applyingHeldKeys`
  这道守卫让"点亮"不会被当成新按下的键（否则会打回`handleLiveNoteOn`，无限循环）。
- **焦点分家**：JUCE 里焦点组件的 `keyPressed` 先于挂在窗口上的全局快捷键，所以窗口里
  `1–6` 会被键盘吃掉（正确的：它现在是乐器），而焦点在别处时一切照旧；窗口失去焦点时
  JUCE 自己会把按着的键松开，不留挂音。

### 三、琶音器

先想清楚它**是什么**：不是轨道效果，是**演奏者**——把按着的键变成一串实时音符。这一条决定
了后面几乎所有事：不碰渲染路径（只作用于实时输入）、生成的音照旧过该轨的音量与效果器、
照旧能被录制、照旧被踩着的踏板挂住。

- **纯逻辑在 `Core/MidiArp.{h,cpp}`**：`Settings`（速率 / 自由 Hz / 方向 / 八度 / Gate /
  Swing / 力度模式 / 固定力度 / Hold）+ `stepTicksFor` / `stepSecondsFor` / `gateTicksFor` /
  `offsetTicksForStep` / `orderFor` / `noteForStep` / `velocityForStep` / `updateLatch` /
  `settingsToVar` / `settingsFromVar`，全部可直接单测。
  互文件不开 `Types.h`（`Types.h` 反过来要 `midiarp::Settings`），所以 PPQ 是**参数**传进去的。
- **时钟两套**：走带跑着 → 用 `TempoMap` 把工程位置换成 tick，步进就锁在小节上、跟着速度变化；
  走带停着 → 它自己的 tick 计数（从按下的第一个键起算，按当前速度折成 tick）。
  两套共用同一段"现在在第几个格、这一格该弹什么"的算术。
- **1 ms 的 `ArpTicker`**：只在"开着而且有东西弹"时跑（与波表光标、混音台表同一条纪律）。
  每个脉冲只推进一步，慢了就跳过漏掉的格，**不会补成一堆和弦**。
- **Hold 的 latch**：`LatchState` 记住"这一组"；全部松开以后组还在跑，下一个按下的键开始新组。
- **录制**：琶音生成的音走与手弹完全一样的录音路径，但**起始 tick 与长度取琶音的意图值**
  （格 tick 与 `Gate × 步长`），不取 note-on 落到音频块上的时刻。实时监听与所有实时音符一样
  受音频块量化（默认 512 帧 ≈ 10.7 ms），录进片段的却是整齐的——这是 D199 明确写下的取舍。
- **界面**：`Source/UI/ArpControls.{h,cpp}` 是**两个窗口共用**的一排控件（5 列 × 2 行），
  读写的都是 `Project::midiInput.arp`，所以两处永远一致；它是**配置**，不进撤销栈。

## 第四十八批：虚拟键盘的卡音修复 + 折叠置顶小窗 + 巴扬模式与电脑键盘图示（已完成）

用户的反馈与要求：**「使用虚拟键盘时，有时候松开键盘仍在持续发声」**，另外要**折叠成小窗**、
**可以显示在其他窗口上层**、**巴扬模式**（`q a z w s x…/` 连续半音、默认 `w` = C、可左右移动
n 个或 12 个半音）、**电脑键盘图示**（白键画白、黑键画黑）。追加一条：**数字排那 14 个键
（含 `·`）按"上五度下四度"排成低音**、要有**独立的低音移位**，以及**虚拟键盘开着时屏蔽
`1–6` 的频率比快捷键**。

### 一、卡音的根因（读代码读出来的，不是猜的）

JUCE 的 `MidiKeyboardComponent::keyStateChanged` 是这么记"哪些电脑键按着"的：

```cpp
auto note = 12 * keyMappingOctave + keyPressNotes[i];      // 按算出来的音号记账
if (keyPresses[i].isCurrentlyDown()) { if (! keysPressed[note]) { keysPressed.setBit(note); state.noteOn(...); } }
else                                 { if (keysPressed[note])  { keysPressed.clearBit(note); state.noteOff(...); } }
```

而 `setKeyPressBaseOctave` 只干了一件事：`keyMappingOctave = newOctaveNumber;`——**不释放任何东西**。
于是"按住一个电脑键 → 换八度"以后：note-on 发的是**旧音号**，之后所有的 keyStateChanged 都在
看**新音号**，`keysPressed[旧音号]` 永远为真、**旧音号的 note-off 永远不会发出来** →
那个音一直响；而新音号那次 `keysPressed` 是空的，所以再按同一个键又会 `noteOn` 一次并把它
记上，松手时发的是新音号的 note-off——听上去就是"有时候松开还在响"，而且是**同一个键会变成
死键**（换回原偏移时 `keysPressed[旧音号]` 还立着）。

修在"谁发起的谁负责放"这一侧：面板用 `startedNotes` 记住**这个窗口发起的音**（鼠标 + 电脑键盘；
从硬件镜像进来的不算），任何结构性变化（两排移位、切布局、折叠、隐藏 / 关闭窗口、析构）都先
`releaseWindowKeys()`：

1. 对每个 `startedNotes` 里的音调 `keyboardState.noteOff`（这条路**会通知监听器** →
   `handleLiveNoteOff` → 引擎真的收音），清空这份集合；
2. 再 `setUpKeyMappings()` 重装键位表——`clearKeyMappings()` 顺手把 JUCE 那份
   `keysPressed` 记账清干净，于是"换回原偏移"之后同一个键照旧能弹。

**刻意没做**「按来源计数」（同一个音被硬件和鼠标同时按着时谁先松谁收音）：有些键盘会中途重复
发 note-on，计数会让它多一层，反而更容易造出卡音。自检两条都断言了：换八度之后引擎里声部归零、
键不再亮，而**同一个键在新八度上照旧出声**。

### 二、折叠小窗 + 置顶

面板两套排布：展开 980 × 460（力度 / 置顶 / 折叠 / 状态行 + 布局 / 两排移位 / 键盘 / 图示 /
琶音）、折叠 520 × 120（**只留那一行控件 + 电脑键盘图示**，键盘条与琶音面板是**藏起来**

这些状态（`alwaysOnTop` / `collapsed` / `layout` / `melodyShift` / `bassShift` / `velocity`）
记在 `%APPDATA%\NiDaw\keyboard.json`——照 `midi.json` 的老写法，缺字段取默认、载入时全部夹取；
自检用 `setSettingsFileForTesting` 指到自己的目录（否则会读写用户真实的那个文件）。

### 三、巴扬模式：旋律排 + 低音排（一张表）

新增 `Core/KeyboardLayouts.{h,cpp}`，**键位、图示、钢琴上的字母共用这一张表**：

- `physicalBoard()`：44 个键帽的真实位置（数字排 `· 1…0 - = ⌫`（`⌫` 两格宽）、三排字母键
  各带自己的缩进），只有位置、没有映射；
- `capsFor(layout)`：把映射填进去。**常规** = 下排 `Z S X D C…M` 一个八度 + 上排
  `Q W E R T Y U` 与数字 `2 3 5 6 7` 组成的高八度；**巴扬** = 三排字母键按列各三个半音
  （`q a z w s x…/` 一路半音往上，30 个键 = 30 个半音）+ 数字排那 14 个键是低音排；
- `baseNoteFor`（常规 60、巴扬 57，即 `w` = C4）与 **`bassNoteFor`**：低音排每个键比前一个
  **高五度**，整排**折返进 C2–C4**：

```
· = F#2   1 = C#2   2 = G#2   3 = D#2   4 = A#2   5 = F3   6 = C4
7 = G3    8 = D3    9 = A3    0 = E3    - = B3    = = F#3  ⌫ = C#3
```

  （`5 → 6` 是**上五度**、`6 → 7` 是**下四度**，正是用户说的"上五度下四度"。）

用户最初只给了 `1…0 - = Backspace`，随后追加"请把 · 键也加上"——于是低音排是 14 个键，
`·` 在五度圈的最左端（F#2）。**为什么必须折返**：严格"每键 +7 半音"的 14 键链跨 **91 个半音**，
比 88 键的 87 个半音还宽，再叠加 `5` = F / `6` = C 这两个锚点，两端一定掉出钢琴。

`·` 那个键还有个小坑：它在中文布局下产生的是 `·`（U+00B7），而 JUCE 的
`KeyPress::isKeyCurrentlyDown` 会 `VkKeyScan` 一下把字符换成虚拟键码——实测本机
`VkKeyScan(U+00B7)` 是 **-1**（不可映射），而 `VkKeyScan('`')` = **VK 0xC0**（正是那个物理键）。
所以键位表里用的是 `KeyPress('`')`（96），它在中英两种布局下都能正确定位到那个键。

两排的移位各自独立：旋律 `-1 +1 -12 +12`，低音 `-1 +1 -5 +5`（五度 = ±7 个半音）。
低音的移位也走折返（任何偏移都不越界），按钮夹在 ±11——因为 12 个半音 = 12 个五度 =
84 个半音 = 恰恰 7 个八度，折返之后是**同一组音**。

### 四、电脑键盘图示与钢琴上的字母

`ComputerKeyboardView` 按 `physicalBoard()` 画四排错位的键帽：每个帽按它对应的钢琴键上色
（**白键帽画白、黑键帽画黑**，文字反色），帽里写电脑键、下面小字写音名，没映射的键淡灰、
按着的键叠一层 accent。`LetteredKeyboard`（`MidiKeyboardComponent` 的薄子类）在
`drawWhiteNote` / `drawBlackNote` 里补一层电脑键字母——**一个琴键可能有多个**
（巴扬下 C4 同时是旋律的 `w` 与低音的 `6`、B3 是 `z` 与 `-`），所以字母用 `·` 连起来
（`keyLettersFor` 就是干这个的，自检直接断言 C4 是 `6·W`、B3 是 `-·Z`）。

### 五、`1–6` 让位

`MainComponent::keyPressed` 里那段频率比快捷键加了 `! isVirtualKeyboardVisible()`：虚拟键盘
在屏幕上时 `1–6` 一律不选频率比（巴扬下它们是低音排、常规下 `2 3 5 6 7` 也在弹音），
窗口一关立刻恢复；音符编辑栏上的比率**按钮**与其它快捷键不受影响。自检两条都验了

### 一、卡音为什么还在：上一批修的是三条路，不是根因

第四十八批补的是"结构性变化"（移位 / 换布局 / 折叠 / 关窗）三条路。但**普通的一次松键**也会漏，
因为电脑键盘的弹奏原来完全交给 JUCE 的 `MidiKeyboardComponent`：

- 它**只在焦点组件（或父链）上**跑 `keyStateChanged`——所以打开窗口（`grabKeyboardFocus` 在
  peer 还没激活时抢不到）或点过任何控件之后，**必须先点一下钢琴键**才能弹（用户报告的第三条）；
- 它按**算出来的音号**记账（`keysPressed[note]`）。**只要有一次 key-up 没送到**（焦点被拿走、
  切窗口、点控件…），那个音号的 note-off 就**永远不会发出来**——声音一直响；而新音号那次
  `keysPressed` 是空的，所以同一个键再按时会重新记上，换回原偏移时又会因为旧音号的记账位还
  立着而**按不响**（"死键"）。上一批的重装键位表只在那三条路里发生，普通松键漏掉的那一次
  没人管。

所以这一批把**弹奏本身**收进面板：

```cpp
bool VirtualKeyboardPanel::keyStateChanged (bool)
{
    updateTyping();          // 按当前布局逐个 poll KeyPress::isKeyCurrentlyDown
}
```

`typingDown` 是面板自己的"哪些电脑键按着"，差分之后经 `keyboardState.noteOn/noteOff` 驱动
（钢琴照样亮、监听器照样转发给 `MainComponent`）。好处一次到位：

- 事件沿父链上浮，所以焦点在窗口里**任何控件**上都行——打开窗口、点过琶音/布局/力度之后都能
  直接弹（文本框除外，那条与"空格让给文本框"同一条规则）；
- "哪些键按着"这份状态在**我们**手里，于是有了可自查的对象。

兜底是 **100 ms 心跳**（只在窗口可见且 `typingDown` 非空时跑）：

1. 复查 `typingDown`：已经不按了的**补一条 note-off**（漏掉的 key-up 自愈）；
2. 窗口（含子件）失去键盘焦点 → 整批放掉（"按住键去点别的窗口"＝声音停，这也符合直觉）。

`releaseWindowKeys()` 仍然是结构性变化的入口，但它现在按 **(触发源, 音)** 逐个放——第四十八批
那版只按音号放，换成"每来源一条"之后就会放错条目（这是这一批自己踩到的：先写好了
`releaseTypingKeys()`，忘了它也走触发源，结果"失去焦点放掉"那条自检失败——正好说明自检在替
我们看住这类细节）。

自检的那几条原话：

```
ok    直接敲电脑键就出声（没有点过钢琴键；引擎里 1 个声部）
ok    （假装那一次松键事件丢了：音还响着，窗口也以为它还按着）
ok    心跳发现键已经松开，把那个音放掉了（不再一直响）
ok    窗口失去焦点时整批放掉（按住键去点别的窗口＝声音停）
```

（为了让整条链路能在离屏跑，面板加了 `setKeyDownForTest` / `simulateMissedKeyUpForTest` /
`runTypingWatchdogForTest` / `setWindowFocusedForTest` 四个钩子：伪造"系统说这个键按着"、
伪造"那一次 key-up 事件根本没来"、手动敲一拍心跳、伪造窗口失焦。）

### 二、低音排：从"每键 +7 再折返"改成"严格交替"

第三版的低音排是"每个键比前一个高五度，然后折返进两个八度"，于是出现用户看到的现象：
`3→4` 和 `4→5` **连着两个上五度**（折返把其中一次变成了"没折到"）。用户要的是**每一对相邻键
交替**：上五度、下四度、上五度、下四度……

改法直接了当——写一张**相对 `5` 键的偏移表**（不再有折返）：

```
键:   ·   1   2   3   4   5   6   7   8   9   0   -   =   ⌫
偏移: +1  -4  +3  -2  +5   0  +7  +2  +9  +4 +11  +6 +13  +8
音:  F#3 C#3 G#3 D#3 A#3 F3  C4  G3  D4  A3  E4  B3 F#4 C#4
```

（`5` = F3、`6` = C4 是用户给的锚点；整排 C#3–F#4。相邻两键的差：`-5, +7, -5, +7, …` 严格交替。）
它与旋律排（A3–D6）**有意重叠**——见下一节。

### 三、每来源独立声部：重叠不再是冲突

原来 `MainComponent` 的音符记账是"一个音一条"（`HeldKey` 只按音号找），于是同一个音被两个键按着
时，先松手的那一方会把音收掉。现在记账改成**一个 (触发源, 音) 一条**：

- 触发源编号：硬件 `0`、鼠标 `1`、电脑键 `100 + 键码`（同一(源, 音)的重复 note-on 仍然忽略——
  这条是为了继续挡住某些硬件键盘的重复 note-on，那才是真正会造卡音的东西）；
- 面板在调 `keyboardState.noteOn/noteOff` 之前把 `currentTrigger` 设好，监听器用它转发；
- 读"现在按着哪些音"的地方（高亮、琶音的 held 集合、音符数）取**去重后的音集合**。

于是巴扬下旋律的 `x` 与低音的 `8`（都是 D4）同时按着会响**两个声部**，各松各停；硬件键盘与
电脑键按同一个音也一样。自检把这条链路整段跑了一遍（2 声部 → 松一个剩 1 → 全松归零）。

### 六、用户报「虚拟键盘按下没有声音」——补最后一段

交付前用户又报了一次"按下没有声音"。查下来不是声音链路坏了，而是**焦点在哪**：

`VirtualKeyboardWindow` 打开时会 `toFront(true)`，这条会把键盘焦点交给**窗口本身**（不是钢琴
组件，也不是面板）。而面板的电脑键轮询只挂在自己的 `keyStateChanged` 上，事件落在窗口上时
**根本走不到面板**——于是"打开窗口直接敲键盘"这条恰恰失效，「点一下钢琴键」也不一定能把焦点
拉回面板。前一次只修了"100 ms 心跳 + 失焦放音"，没修"事件根本到不了面板"。

修法两条：

1. 面板同时实现 `juce::KeyListener`，窗口构造里 `addKeyListener (panel)`——焦点落在窗口自身
   时，`keyPressed / keyStateChanged` 会从窗口转给面板（`panelIsKeyListener` 自检守住这条）；
   `show()` 里再 `focusTyping()` + `callAsync` 补一次，让面板自己拿焦点是常态。
2. 补了两条**真鼠标路径**的血检（此前只有走 `MidiKeyboardState` 的合成钩子，两条路可能不一致）：
   `pressKeyWithMouseForTest / releaseKeyWithMouseForTest` 走 `keyboard.mouseDown / mouseUp`，
   断言**这一轨的电平表真的动了（峰值 0.0601）**、**松开那一刻 note-off 就到引擎（不留挂音）**、
   **松手后余音会衰下去（0.0000 对 0.0601）**。于是"点得出声"和"敲得出声"两条路都在离屏环境里
   被证明过，不再只靠人眼。

最终：断言 **34 组 / 2648 条**全过，自检 **1335 项 / 50 张快照**全过。
（另：交付前一定要跑 `work\make_release.bat`——用户从 `outputs\` 拿到的 exe 若是上一批的，
改动再多也听不到。）

**教训**：这三批下来，"事件驱动的漏路径"咬了两次——第一次以为是通道记账，第二次只补了结构性
路径。真正管用的做法是**把状态收到自己手里 + 定时自查**；以后再写这类"跟随外部输入"的功能，
默认就该带一条心跳兜底。

## 第五十二批：粒子合成器（已完成）

用户要的第六种内置乐器：从**导入的音频文件**里撒颗粒。先按老规矩把这一批拆成"模型 → 引擎 →
界面 → 测试 → 文档"，并且一开始就把几个会影响实现的取舍问清楚（音源从哪来、音源怎么存、
编辑器什么形态、音符频率怎么用、参数做多少、散点接不接鼠标、工厂预设要不要、扫描到头怎么办）。

**模型**：`TrackKind::granular` **追加在最后**（老的 0–6 序号一动不动），`GranularParams` 挂在
`InstrumentTrack.granular`，`.nprj` 的轨道多一个 `granular` 段（缺字段取默认，旧工程照常打开）；
共享转换函数放在 `PresetStore.h`，所以工程与 `presets.json` 的 `granularPatches` 段用同一套格式。

**引擎**（`Audio/GranularSynth.{h,cpp}`）：16 声部（沿用 `kVoicesPerTrack`），每声部最多 32 颗
颗粒，满了丢最老的一颗。每颗颗粒有自己的起点、自己的速率、自己的长度：速率 = `音符频率 ÷ 根音`
（和采样器一字不差，所以参考线系统的精确频率照样成立），再乘 ±音高抖动，反向概率命中就倒着读；
起点 = `位置 + 扫描速度 × 已按下时长 + 位置包络 × 包络量`（`fold01` 折返）± 位置抖动；窗形固定
Hann；整条云的输出按 `1/√(密度 × 粒度)` 补偿重叠，所以把密度拧大改变的是质地而不是音量。
`buildSchedule` 让粒子轨与采样器**共用同一段取样本的代码**与同一份解码缓存（`TrackRenderInfo.sample`），
`PlaybackEngine::granularSynths` 与 `synths` / `samplePlayers` 平行，试听通道、插入链、推子、
电平表、MIDI 输入、录制、导出全都自动跟上。

**界面**（`UI/GranularEditor.{h,cpp}`）：780 × 640 的单页（走第四十六批那条"按页取高度"的路），
预设行（只有"我的"）→ 文件行 → **波形 + 只读实时颗粒散点**（横轴取样位置、纵轴颗粒年龄，
刚出生的点更亮，另有一条扫描线；30 Hz 刷新，画面没变就不重绘）→ 四列参数（颗粒 / 取样 +
输出 / 位置包络 + 音量包络 / 滤波器）→ 试听键盘。给编辑器的数据是引擎**上报**的颗粒快照
（最多 64 颗的原子读数），和第四十六批波表光标同一套做法：画出来的必须是正在响的那一颗。
`＋ 新建轨道` 从七项变八项（粒子合成器插在采样器之后，两者都是"自带音频"的乐器）。

**测试**：新单测组 `Granular`（46 条）。写的时候踩了三个坑，都记在这儿备查：
① 渲染辅助函数原来按整块渲染、只保留前 N 个采样，于是"1 秒之后的扫描位置"其实是 48128 个采样
之后的——引擎数的和测试数的不是一个时间；改成**恰好渲染 total 个采样**。
② 测频率时用 20 颗/秒的密集云，所有颗粒都从同一个源相位起步，整条云是 20 Hz 周期的，过零率会
锁到 440（源的频率）而不是 436.043——**测量方法**的问题，不是引擎：改成"一次只有一颗长颗粒，
在它的中段测量"，量出来就是 436.043。
③ 一次访问空 vector 的 `front()` 造成访问违例，被自检的崩溃处理器抓了个正着（顺便发现原来
`.ps1` 直接双击式的调用会卡住——用 `powershell -File` 跑就正常，交付脚本本来就是那么写的）。
离屏自检 +34 项 + 新快照 `51-granular.png`（50 → 51）。**顺手修掉一个真 bug**：`PresetStore::load()`
原来只 clear 了四个容器，其余段（midiMaps / 减法 / 波表 / 鼓机）会跨两次 load 叠加，现在全清。
基线：单测 **35 组 / 2724 条**、自检 **1377 项 / 51 张**。

### 交付后修：粒子合成器的试听键盘"一直响"

用户报「用粒子合成器界面的键盘会一直响，播放后也不停」。根因一眼可见：
`PlaybackEngine::applyPreview` 的**松开那一段**（`! gate && previewRunning`）把 fm / 采样器 /
减法 / 波表 / 鼓机逐个 `noteOff` 了一遍，唯独漏掉了这一批新加的 `previewGranular` —— 于是试听
声部永远等不到 note-off，放大器包络一直挂在保持段上，云当然不散；编辑器的散点也跟着一直重绘
（所以看起来"停了但还在动"）。**加一行** `previewGranular.noteOff (kPreviewNoteId);` 就好。

教训和第四十九批那次同源：**"每一种乐器都要在这个 switch 里出现一次"这种事，漏一个不会有任何
编译警告**（`if/else` 链与逐项列举最容易漏）。所以补了两条回归：单测
`Granular / 试听通道：松开以后云端停下来`（按下去有颗粒 → 松开 → 颗粒数归零 + 预览声部回收），
以及自检里的一条「松开以后颗粒云停下来（还剩 0 颗）」。基线：单测 **35 组 / 2727 条**、
自检 **1378 项 / 51 张**。

## 第五十批：电脑键盘的轮询 + "系统报告了哪几个键"（已完成）

用户报：「有时在按下多个按键时会产生冲突，例如按下 `z x c` 三个按键时只有两个响应。」

先查软件侧：整条链路（面板轮询 → `MidiKeyboardState` → `MainComponent::handleLiveNoteOn`
→ 实时音符 FIFO → 乐器）都不会因为"同时三个音"而丢东西——FIFO 是 512 个事件、每个电脑键各有
自己的触发源编号（`100 + 键码`），三个键就是三个声部。于是把两件事分开做：

**① 不再只靠事件送到面板（`UI/VirtualKeyboardWindow`）。** 面板原来只在 `keyStateChanged`
里轮询，而这条事件要沿父链上浮才能到它——被谁吃掉、或者焦点正好不在窗口里，这一次按键就没了。
现在窗口**在屏幕上时**就挂一个 30 Hz 的定时器，每个 tick 按当前布局读一遍
`KeyPress::isKeyCurrentlyDown`（Windows 上就是 `GetAsyncKeyState`，驱动报告的真实状态），
与自己的"按着"集合做差分；原来的 100 ms 心跳规则（漏掉的 key-up 自愈、失焦整批放掉）并到同一个
tick 里。代价是每 33 ms 约 30 次键状态查询，可以忽略；换来的是**整类**"某个事件被谁吃掉"
的问题一起消失。

**② 把"系统送来了哪几个键"写在屏幕上。** 既然软件侧已经证明"多少个键都能响"，那么"按三个只响
两个"就只剩两种可能：第三个键根本没送到 Windows（键盘的 key-rolling 有限，`z x c` 这种相邻的
下排键正是最常见的例子），或者它送到了但没绑频率。状态行现在在**有键按着时**多一句
`· 系统报告按下的键：Z X C`——按住三个却只列出两个，当场就能判定是键盘。不按键时状态行与
以前一字不差（快照也不变）。

顺带修一处：`focusIsInsideWindow()` 原来把"当前没有任何组件有焦点"也算成"失焦"。常驻轮询让这条
从"漏事件时的兜底"变成"每 33 ms 执行一次"，而离屏自检里根本不存在真焦点——它会把刚按下的音
打掉。现在只有焦点**明确落在别的组件上**才放掉（真实世界里"用户去了别的窗口"走的就是那一条）。

自检新增 4 项：`z / x / c` 一起按 = **3 个声部**、状态行列出 `Z X C`、松开其中一个还剩 2 个声部、
再松一个只剩 1 个。断言仍 **34 组 / 2648 条**，自检 **1339 项 / 50 张快照**（`49` 那张快照没有
变化：状态行的新句子只在按住键时出现）。发布时 `work\run_tests22.ps1` 与 `make_release.bat` 全绿；
另有一次运行里"16 个音用满 16 个通道"那条 VST 断言抖了一次（12 个），重跑即绿——它与本批无关，
是那条断言本身的时序敏感（它依赖 `setUpChords` 之后再让消息线程跑一轮），记在这里备查。

## 第五十一批：低音排的八度按钮（已完成）

用户要求「增加按键使低音按键可以上下移动 12 个半音」。

低音排原来只有 `半音 ±1` 与 `五度 ±7` 两组按钮，而且 `bassShiftRange()` 硬写着 ±11。那个 ±11
是**折返版**低音排留下的：第四十八批的整排折在 C2–C4 里，再往上挪 12 个半音折回去还是同一组音，
所以按钮按下去"看着动了、其实没变"，当时才把它卡住。第四十九批把低音排换成**固定的偏移表**
（无折返、无越界）之后，这个理由已经不存在了：`+12` 就是一个真正的八度。

改法两行：

1. `bassShiftRange()` 不再写死，按 `ShiftRange` 在头文件里本来该有的含义（"这一排还能挪多远
   才跑出钢琴"）算出来——整排最低的 `1`（C#3）与最高的 `=`（F#4）正好在 A0 / C8 上卡住，
   于是可移范围是 **-28 … +42**。旋律排本来就是这么算的，两排现在同一套规则。
2. 第二行加上 `-12` / `+12` 两个按钮（展开 30 px、折叠 20 px；折叠时控件照旧全留），与
   `半音`、`五度` 共用同一个偏移量，所以三个按钮可以叠着用（例如先 `+5` 再 `+12`）。

单测 `KeyboardLayout` 的「移位范围与越界夹取」13 → 43 条：断言 `-28` / `+42`、整排最低与最高
的键在两头**刚好**落在 A0 / C8、以及整排 ±12 逐键同向移动 12 个半音。自检新增 4 项：
`低音八度移位：整排往上 12 个半音（5 = F4，旋律不动）`、往下的两下就是下面那个八度（`5 = F2`）、
`低音偏移顶到 +42 就停住（整排还在钢琴上）` / `另一头停在 -28`，以及两个新按钮在**展开与折叠**
两种布局里都有真实尺寸。断言 2648 → **2678** 条，自检 1339 → **1343** 项（其余快照不变：
第二行变宽了一点，但没超出 980 的设计宽度）。
