## 本机代码签名：双击不再提示「无法验证发布者」

- 现象：双击 `HM.exe` 时 Windows 报「无法验证发布者」。核查：exe 未签名（`NotSigned`），
  清单是 `asInvoker`（不请求提权），文件也没有 MOTW，本机装了 Defender + McAfee + 火绒。
- 做法（只对本机当前用户有效）：
  - `work\signing\new_hm_signing_cert.ps1`：生成 `CN=HM, O=HM, OU=Local build` 的自签名
    代码签名证书（RSA 3072 / SHA-256 / 5 年），导出 `.cer`，把证书装进
    `Cert:\CurrentUser\Root`（`certutil -addstore -user Root`，`Import-Certificate` 拒绝
    无界面写 Root）和 `Cert:\CurrentUser\TrustedPublisher`。
  - `work\signing\run_sign.ps1 <exe...>`：用 `signtool sign /fd SHA256 /s My /sha1 <thumbprint>`
    签名，并断言 `Get-AuthenticodeSignature` 为 `Valid`。
  - `make_release.bat` 新增 `[1b]`：主程序构建完先签名，签名失败即中止发布。
- 验证：`outputs\HM\HM.exe`、`outputs\HM-win64\HM.exe`、开发版三份都是
  `Status = Valid`、签名者 `CN=HM, O=HM, OU=Local build`。
- 边界：这张证书只在**这台机器、这个 Windows 账户**里受信任。发给别人仍然显示未知发布者，
  要彻底解决只能买/申请受信任的代码签名证书（OV/EV，或 Azure Trusted Signing），到时把
  `run_sign.ps1` 的 thumbprint 换成新证书即可，发布流程不用改。

## SmartScreen 仍然拦截（同日）

- 自签名后 `Get-AuthenticodeSignature` 是 `Valid`，但双击仍弹「Windows 已保护你的电脑」。
  原因是 SmartScreen 的**应用信誉**检查只认微软信誉库里的发布者，自签名证书不在其中——
  签名能改「发布者」显示，改不了 SmartScreen 的放行决定。
- 按用户选择关掉本机的「检查应用和文件」：
  - `HKLM\SOFTWARE\Policies\Microsoft\Windows\System` 的 `EnableSmartScreen`（DWORD）= 0
  - `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer` 的 `SmartScreenEnabled`（SZ）= `Off`
  - 重启 Explorer 使设置立即生效；脚本 `work\disable_smartscreen_app_check.ps1`（需管理员）。
- 撤销：删掉这两个值、重启 Explorer，或到 Windows 安全中心把开关打开。
- 只影响这台机器；对外分发仍必须用正式 CA 证书，SmartScreen 才会认发布者。

## Serum 预设的调研结论（未实施）

- 本机 `C:\Users\ASUS\Documents\Xfer\Serum 2 Presets` 有 626 个 `.SerumPreset`。
- 文件格式：`XferJson\0` + 8 字节小端元数据长度 + 元数据 JSON（只有名字/作者/标签等）；
  其后是 8 字节头 + **zstd** 压缩的参数树（约 32 KB，键如 `kParamEnabled`），不是公开文档的格式。
- 可行性：需要在 C++ 侧引入 zstd（JUCE 不带），再逆向参数树到 `HybridParams` 的映射，

  只能做「用户自己选文件」的运行时导入。
- 结论：作为独立的一批再做；本批混合器仍是原创的 48 个（含 Reese/neuro 风格的尝试）。
