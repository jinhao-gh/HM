# 开发日志

每天一个文件，命名 `YYYY-MM-DD.md`，记录当天**完成**了什么、还剩什么**待办**、
以及当天做出的**决策与发现**。

## 记录规则

- **只有实际发生的事**。没有开发活动就写一行「今日无开发活动」，**不要为了填满而编造**。
- **待办要能直接执行**：写「参考组界面：完成圆点与叉点的交互」，不写「继续开发」。
- **决策要带理由**，尤其是被否决的方案，避免以后重复讨论；稳定性值得的决策同时要同步进 `../docs/`。
- **踩到的坑要写下来**，包括怎么定位的。这类记录以后最省时间。
- **验证结果要带数字**：跑了几组测试、测得频率是多少、有没有警告，不要写「测试通过」了事。

## 文件结构

```markdown
# YYYY-MM-DD 开发日志

## 完成
## 待办                     <- 未完成的顺延到次日
## 决策与发现
## 验证
```

模板见 [TEMPLATE.md](TEMPLATE.md)。

## 自动记录

已配置每日定时任务（22:00 本地时间）：读取本目录，为当天创建或更新日志文件。
内容来源是当天的实际开发活动——本线程里的工作、`../Source/` 下最近修改的文件、
以及前一天尚未完成的待办。

因此**未完成的待办会被自动顺延**，不需要手工搬运。
